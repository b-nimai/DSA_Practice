# 10. 134. Gas Station (LC 134) — Medium
🔗 [Open on LeetCode](https://leetcode.com/problems/gas-station/)

**Pattern:** Greedy — **one pass, one running accumulator, restart the candidate on failure**. Same skeleton as [[9-763-partition-labels|763]] / [[8-45-jump-game-ii|45]] (carry a running value, act at a threshold), but the running value is a **prefix sum that must never go negative**, and the greedy move is a **jump-forward restart** instead of a cut. Secretly the **circular-array prefix-sum** trick: it's Kadane's reset with an index as the payload.
**Trigger:** "**circular route**" + "**start at some index and come back around**" + "**return the starting index, guaranteed unique**". The tells are (a) each stop has a **local gain and a local cost** ⇒ collapse to a single `diff[] = gas[] - cost[]`, (b) the constraint is a **running total that must stay ≥ 0 at every step**, not just at the end, (c) `n ≤ 10⁵` kills the obvious O(n²) "simulate from each start". Whenever "if I fail somewhere, every start in between is also doomed" is provable, you get an O(n) single pass instead of n restarts.

## Problem (1-liner)
`n` gas stations on a **circle**; station `i` gives `gas[i]` fuel and it costs `cost[i]` to drive from `i` to `i+1` (wrapping). You start with an **empty tank**, capacity is **unlimited**; return the **unique** start index from which you can complete the whole loop, or `-1` if none exists.
**Examples:** `gas=[1,2,3,4,5], cost=[3,4,5,1,2] → 3` (`diff = [-2,-2,-2,3,3]`, total `0`) · `gas=[2,3,4], cost=[3,4,3] → -1` (`diff = [-1,-1,1]`, total `-1`) · `gas=[5], cost=[4] → 0` (n=1 — one "trip" from 0 back to 0) · `gas=[2], cost=[3] → -1` · all-zero arrays → `0` (total `0`, every start is legal).
**Constraints:** `n == gas.length == cost.length`, `1 ≤ n ≤ 10⁵` — **never empty**, so no empty guard. `0 ≤ gas[i], cost[i] ≤ 10⁴` ⇒ each `diff[i] ∈ [-10⁴, 10⁴]` and the total fits in **`int`** (`|total| ≤ 10⁹ < 2³¹`). "**The answer is unique**" is a gift you should *use* out loud, not just note.

## Idea (1-liner)
Work on `diff[i] = gas[i] - cost[i]`: **`sum(diff) < 0` ⇒ `-1`, otherwise a start is guaranteed to exist**; sweep once keeping a running `tank`, and the moment it goes negative at `i`, **the whole block `[start..i]` is dead** ⇒ jump `start = i + 1`, reset `tank = 0`.

## Approach
1. Collapse the two arrays into one signed quantity: `diff = gas[i] - cost[i]` (net fuel gained by making hop `i → i+1`). The problem is now: **find a rotation of `diff` whose every prefix sum is ≥ 0.**
2. Keep two accumulators — `total` (sum of **all** diffs, **never** reset) and `tank` (sum since the current candidate `start`).
3. For `i = 0 .. n-1`: add `diff` to both. If `tank < 0`, set `start = i + 1` and `tank = 0`.
4. After the loop: `return total < 0 ? -1 : start;`

> **Load-bearing insight #1 — feasibility is decided by ONE number.** If `sum(gas) < sum(cost)` the circuit is impossible from anywhere (you'd have to manufacture fuel). If `sum(gas) >= sum(cost)`, a valid start **always exists** — so you never *search* for existence, you only *locate* the index. Concretely: let `P[k]` be the prefix sums of `diff`; starting at `s`, the tank at step `k` is `P[k] - P[s-1]`, so picking `s = argmin(P) + 1` makes every partial sum ≥ 0 by construction. That's the existence proof — and also an alternative algorithm (see below).
>
> **Load-bearing insight #2 — the skip lemma is what buys O(n).** If starting at `s` the tank first goes negative on arriving at `f`, then **no index in `[s, f]` is a valid start.** Why: coming from `s` you reached every intermediate `k ∈ (s, f)` with `tank ≥ 0`. Starting *at* `k` instead means arriving at `f` **without** that non-negative carried-in surplus ⇒ you arrive with **≤** the fuel you had before, which was already negative. So the entire failed block dies at once and `start` only ever moves **forward** — one pass, no restart, no wraparound simulation.
>
> **Load-bearing insight #3 — you never simulate the wrap.** The final `start` is only ever checked on the suffix `[start, n-1]`; the wrapped prefix `[0, start-1]` is never re-driven. It doesn't need to be: `total ≥ 0` plus "the suffix from `start` never dips" forces the wrapped part to stay non-negative too — you enter it carrying `total` minus the prefix's deficit, which dominates every partial deficit in it. The `total` check is doing double duty as **feasibility test** *and* **wrap-around certificate**; that's the whole elegance of the two-accumulator version.

## Code (clean canonical)
```cpp
class Solution {
public:
    int canCompleteCircuit(vector<int>& gas, vector<int>& cost) {
        int n = gas.size();
        int total = 0, tank = 0, start = 0;

        for (int i = 0; i < n; i++) {
            int diff = gas[i] - cost[i];
            total += diff;                 // never reset — decides feasibility
            tank  += diff;                 // fuel accumulated since `start`

            if (tank < 0) {                // can't even leave i for i+1
                start = i + 1;             // every index in [start..i] is dead
                tank  = 0;                 // restart with an empty tank
            }
        }
        return total < 0 ? -1 : start;
    }
};
```
**TC:** **O(n)** — a single pass; `start` only moves forward.  **SC:** **O(1)** — three ints, `diff[]` never materialised.
*The `total` check comes **after** the loop, it does not replace the `start` logic* — they answer two different questions ("is it possible?" vs "where?") and neither substitutes for the other.

## My Solution
```cpp
class Solution {
public:
    int canCompleteCircuit(vector<int>& gas, vector<int>& cost) {
        int total = 0, start = 0, tank = 0;

        for (int i = 0; i < gas.size(); i++) {
            int diff = gas[i] - cost[i];
            total += diff;
            tank += diff;

            if (tank < 0) start = i + 1, tank = 0;
        }

        if (total < 0) return -1;
        return start;
    }
};
```
✅ **Correct and optimal — O(n)/O(1)**, identical to the canonical version. Both accumulators are present, `tank < 0` is the right (strict) test, and the `total` guard fires before `start` is ever returned, so the out-of-range `start == n` case is safely absorbed.
**Refinements:** `i < gas.size()` compares `int` to `size_t` ⇒ `-Wsign-compare`; hoist `int n = gas.size()`. The **comma operator** in `if (tank < 0) start = i + 1, tank = 0;` works but is a code-review smell (it silently breaks the day someone adds a third statement) — use braces. Finally, `if (total < 0) return -1; return start;` reads fine, but `return total < 0 ? -1 : start;` makes the "one number decides feasibility" insight visible in the code.

## Other Approaches
- **Brute force — simulate every start.** For each `s`, drive `n` steps with wraparound (`(s+k) % n`), bail on a negative tank. **O(n²) / O(1)**. Say it first, then kill it: `n = 10⁵` ⇒ 10¹⁰ steps, hard TLE. Still the right thing to write as a **correctness oracle** when random-testing the greedy.
- **Prefix-sum minimum (`argmin`) — the "why it works" made literal.** Build `P[k] = Σ diff[0..k]`; if `P[n-1] < 0` return `-1`, else return `(argmin(P) + 1) % n`. **O(n) / O(1)**. Same cost, and it's the *proof-shaped* answer — "start right after the deepest dip, because then the whole trough is behind you". Great to name as the alternative derivation; the two-accumulator sweep is the tighter code.
- **Two-accumulator sweep** *(canonical)* — **O(n) / O(1)**. The expected answer.
- **Doubled array + monotonic deque** — concatenate `diff` with itself and find a length-`n` window whose every prefix is ≥ 0, using a deque of prefix minima. **O(n) / O(n)**. Strictly worse here, but it's the honest tool the moment the question becomes "**how many** valid starts?" or "the tank has **capacity C**", where the skip lemma breaks.
- **Follow-ups worth pre-empting:** *"what if the answer weren't unique — return all valid starts?"* → the greedy's single `start` no longer suffices; use the prefix-min formulation and collect every index achieving the minimum. *"what if the tank had finite capacity?"* → excess fuel is lost, the prefix-sum model dies, it becomes a windowed simulation. *"better than O(n)?"* → no, you must read every station.

> **The one-pass-accumulator family to distinguish out loud:** *extend a frontier, **cut** when the index catches it* → [[9-763-partition-labels|763]] / [[8-45-jump-game-ii|45]]. *Extend a frontier, **fail** when the index outruns it* → [[7-55-jump-game|55]]. *Accumulate a signed sum, **restart the candidate** when it goes negative* → **134** and Kadane (LC 53). 134 vs Kadane is the sharpest pair: Kadane resets `cur = 0` when `cur < 0` and carries a running **max**; 134 resets `tank = 0` on the identical condition but carries a running **index**. Same reset, different payload.

## Pitfalls
- **Returning `start` without checking `total`** — *the* signature bug. On `gas=[2], cost=[3]` the loop leaves `start = 1`, an **out-of-range** index; on `gas=[2,3,4], cost=[3,4,3]` it returns `2`, a station you provably can't loop from. The `total < 0` guard isn't bookkeeping, it's half the algorithm.
- **Resetting `total` along with `tank`** — they track different things: `tank` is per-candidate, `total` is global. One shared accumulator cannot answer both questions.
- **Panicking that `start` can equal `n`** — it can, but only when the remaining suffix couldn't recover, which forces `total < 0`, so `-1` returns first and the index is never used. Know *why* it's safe instead of bolting on a defensive `% n`.
- **Testing `tank <= 0` instead of `tank < 0`** — arriving with exactly 0 fuel is legal (example 1 finishes at exactly 0). `<=` discards valid starts.
- **Simulating the wraparound "to be safe"** — an extra `(start + k) % n` verification loop is O(n) wasted work and signals you don't trust insight #3. Explain why it's unnecessary rather than writing it.
- **Rejecting stations where `gas[i] < cost[i]`** — a lossy station is fine if you arrive with surplus; only the *running* sum matters. Same shape as the `nums[i] == 0` trap in [[7-55-jump-game|55]].
- **Restarting the scan at `start` instead of continuing from `i + 1`** — re-driving the skipped block makes it O(n²), which is exactly what the skip lemma exists to prevent. `i` never goes backwards.
- **`int` vs `size_t` in `i < gas.size()`** — `-Wsign-compare`; hoist `int n = gas.size()`.
- **Overflow reflex** — `long long` is unnecessary here (`|total| ≤ 10⁹`), but state the bound out loud instead of guessing; at `gas[i] ≤ 10⁹` it would genuinely be needed.
- **Reaching for DP or a heap** — "circular" + "pick a start" invites over-engineering. The structure is forced, not chosen; there is nothing to optimise over.
