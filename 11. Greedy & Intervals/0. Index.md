# Greedy & Intervals — Index

60-second whole-pattern recall. Read the **Trigger** column and try to recall the **Idea** before peeking.

**Core skeleton (intervals):** **sort first**, then make the locally best choice in one linear pass. Sorting by **start** turns an all-pairs O(n²) overlap question into an **adjacent-pair** O(n) question (if `next.start >= cur.end` holds for neighbours, it holds for every farther pair too). Sort by **start** to *merge / detect / count* overlaps; sort by **end** to *maximise how many non-overlapping intervals you keep* (earliest-finish-first). When you need **max concurrency**, stop scanning and sweep: `+1` on a start, `-1` on an end.

## When to reach for Greedy / Intervals
1. **"Do these intervals overlap / merge them / insert one"** → sort by **start**, one pass comparing to the previous (or last merged) interval.
2. **"Minimum rooms / maximum concurrent X / peak load"** → **sweep line** or a **min-heap of end times** — you need the running count, not a bool.
3. **"Remove/keep the fewest-or-most intervals so none overlap"** → sort by **end**, earliest-finish-first greedy (LC 435, 452).
4. **"Minimum number of …" / "maximum number of …" on sortable input** → suspect greedy; be ready to justify why the local choice is globally safe (exchange argument).

## Common Pitfalls Across the Pattern
- **Forgetting to sort** — every proof in this pattern starts "after sorting". Unsorted input silently gives wrong answers, not crashes.
- **Sorting by the wrong key** — start for *merge/detect*, end for *keep-the-most*. Getting this backwards is the #1 bug in 435/452.
- **`<` vs `<=` on the boundary** — decided by whether the problem treats touching intervals (`[1,4],[4,7]`) as a conflict. Read the statement; never guess.
- **Unsigned `size()` arithmetic** — `size() - 1` wraps on an empty container; loop from 1 and look backwards.
- **Assuming greedy is safe** — it's only valid when the local choice provably can't hurt the future (see the [[7-1046-last-stone-weight|1046 vs 1049]] trap in the Heap pattern: forced order ⇒ greedy, chosen order ⇒ DP).
