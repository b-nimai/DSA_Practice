# Greedy & Intervals — Index

60-second whole-pattern recall. Read the **Trigger** column and try to recall the **Idea** before peeking.

**Core skeleton (intervals):** **sort first**, then make the locally best choice in one linear pass. Sorting by **start** turns an all-pairs O(n²) overlap question into an **adjacent-pair** O(n) question (if `next.start >= cur.end` holds for neighbours, it holds for every farther pair too). Sort by **start** to *merge / detect / count* overlaps; sort by **end** to *maximise how many non-overlapping intervals you keep* (earliest-finish-first). When you need **max concurrency**, stop scanning and sweep: `+1` on a start, `-1` on an end.

| 8 | [Jump Game II](https://leetcode.com/problems/jump-game-ii/) | 45 | M | "**minimum number of jumps** to reach the last index" — reachability is **guaranteed**, so the answer is a **count**, not a bool ("shortest moves on an unweighted line where each position advertises a range" ⇒ BFS) | **[[7-55-jump-game|55]]'s frontier cut into LEVELS — implicit BFS with two ints instead of a queue.** `jumps = curEnd = farthest = 0`, then for `i = 0..n-2`: `farthest = max(farthest, i + nums[i]);` **then** `if (i == curEnd) { jumps++; curEnd = farthest; }`. **Why it's BFS:** level `k` = everything reachable in exactly `k` jumps = a **contiguous window** `[curEnd+1, farthest]` (no holes, since any length `1..nums[i]` is legal), so the queue is fully described by its endpoints; `jumps` is BFS **depth**, and BFS's first arrival is optimal by construction. **Loop to `n-2`, NOT `n-1`** — *the* signature bug: landing on the last index with `i == curEnd` counts a departure you never make (`[2,3,1,1,4]` → **3** instead of 2, `[0]` → **1** instead of 0). A jump is counted when you **leave** a level. **You never pick WHICH index to jump to** — the greedy commits only to the next *window* and defers the choice; `farthest` already tracks the best member. Hence the other classic wrong answer: **greedily jumping to the furthest index (`i += nums[i]`)** gives 3 on `[2,3,1,1,4]` — the optimal first hop is the *nearer* index 1, which launches further. Order inside the loop matters (extend `farthest` before testing `i == curEnd`). `n ≥ 1` ⇒ `[0]` → **0** (loop never runs, no special case). `nums[i] ≤ 1000` here (vs 10⁵ in 55), reachability guaranteed ⇒ **no zero-wall / `-1` path**; if the guarantee is dropped, the signal is `farthest == curEnd`, never `nums[i] == 0`. Ladder: brute O(2ⁿ) → backwards DP `dp[i] = 1 + min(dp[i+1..i+nums[i]])` **O(n²)/O(n)** (AC's at 10⁴) → explicit BFS+visited O(n)/O(n) → **greedy O(n)/O(1)**. Alt phrasing = explicit two-pointer window loop (same cost, makes the level visible, and returns `-1` for free). Don't use Dijkstra — every edge costs 1. Generalises to **1024 Video Stitching** / **1326 Min Taps** (same levels, intervals given explicitly); breaks at **1306** (backwards ⇒ BFS) and **1696** (weights ⇒ deque DP) | O(n) | O(1) |

## When to reach for Greedy / Intervals
1. **"Do these intervals overlap / merge them / insert one"** → sort by **start**, one pass comparing to the previous (or last merged) interval.
2. **"Minimum rooms / maximum concurrent X / peak load"** → **sweep line** or a **min-heap of end times** — you need the running count, not a bool.
3. **"Remove/keep the fewest-or-most intervals so none overlap"** → sort by **end**, earliest-finish-first greedy (LC 435, 452).
4. **"Minimum number of …" / "maximum number of …" on sortable input** → suspect greedy; be ready to justify why the local choice is globally safe (exchange argument).

## Common Pitfalls Across the Pattern
- **Forgetting to sort** — every proof in this pattern starts "after sorting". Unsorted input silently gives wrong answers, not crashes.
- **Sorting by the wrong key** — start for *merge/detect*, end for *keep-the-most*. Getting this backwards is the #1 bug in 435/452.
- **`<` vs `<=` on the boundary** — decided by whether the problem treats touching intervals (`[1,4],[4,7]`) as a conflict. Read the statement; never guess.
- **Unsigned `size()` arithmetic** — `size() - 1` wraps on an empty container; loop from 1 and look backwards.
- **Assuming greedy is safe** — it's only valid when the local choice provably can't hurt the future (see the [[7-1046-last-stone-weight|1046 vs 1049]] trap in the Heap pattern: forced order ⇒ greedy, chosen order ⇒ DP).
