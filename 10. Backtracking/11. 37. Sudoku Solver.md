# 11. 37. Sudoku Solver (LC 37) — Hard
🔗 [Open on LeetCode](https://leetcode.com/problems/sudoku-solver/)

**Pattern:** Backtracking — **constraint satisfaction, solve-in-place**: like [[8-79-word-search|79]] there's nothing to *collect*, the recursion returns `bool` and the answer is the mutated board itself
**Trigger:** "**fill the empty cells** so every row / column / 3×3 box contains 1–9 exactly once, board is modified **in place**, return `void`" → find the next `'.'`, try `'1'..'9'`, keep the ones that are legal, recurse; **if no digit fits, `return false` — that cell's failure kills the whole partial board.**

## Problem (1-liner)
Given a partially filled 9×9 grid (`'.'` = empty), fill every empty cell so that each row, each column, and each of the nine 3×3 sub-boxes contains the digits 1–9 exactly once. Modify `board` in place.
**Example:** the classic `[["5","3",".",...]]` grid → the unique completion `[["5","3","4","6","7","8","9","1","2"], …]`.
**Constraints:** exactly `9 × 9` · each cell is a digit or `'.'` · **it is guaranteed the board has exactly one solution**.
**Edge case:** there is no empty-input case — the grid is always 9×9. The two degenerate ends are an **already-full board** (the scan finds no `'.'`, base case fires immediately, `true`) and a board with **all 81 cells empty** (still solves fast — the first row is unconstrained, then pruning takes over). The uniqueness guarantee is what lets you **stop at the first solution**; without it you'd have to keep searching to prove uniqueness.

## Idea (1-liner)
Walk to the **first** empty cell, try each digit that doesn't already appear in its row / column / box, and recurse — **the entire algorithm is "place, recurse, un-place"**; the only intelligence is the legality test, which is what prunes 9^m down to something that finishes.

## Approach
1. **Find the next empty cell.** Scan the grid for the first `'.'`. If there isn't one, the board is complete ⇒ `return true`.
2. **Try each candidate** `'1'..'9'` at that cell. Test legality with `safe(row, col, ch)`: `ch` must not appear in row `row`, column `col`, or the 3×3 box whose origin is **`(row/3)*3, (col/3)*3`**.
3. **Choose → explore → un-choose:** write the digit, recurse; `if (helper(...)) return true;` — propagate success straight up. Otherwise reset the cell to `'.'` and try the next digit.
4. **If no digit fits, `return false`.** This is the pruning signal: it tells the caller "the digit *you* placed was wrong", and the caller then undoes its own cell and moves on.
5. `solveSudoku` just calls `helper` and ignores the return — the board is the answer.

> **Load-bearing insight:** the `return false` must sit **inside** the "this cell is empty" branch, right after the candidate loop — **not** after the two scan loops. It means *"I found an empty cell and nothing legal fits ⇒ this partial board is dead."* Hoist it one level out and the scan happily moves on to the *next* empty cell, so you can `return true` on a board that still has holes. The mirror-image detail: on the **success** path you return `true` **without undoing** — the filled digits *are* the output, so backtracking only ever happens on the failing path (exactly like the early-exit in [[8-79-word-search|79]]).

## Code (clean canonical)
```cpp
class Solution {
    int rows[9] = {}, cols[9] = {}, boxes[9] = {};   // bitmask: bit d set ⇒ digit d+1 used

    static int box(int i, int j) { return (i / 3) * 3 + j / 3; }

    bool helper(vector<vector<char>>& board, int pos) {
        if (pos == 81) return true;                                   // no cells left ⇒ solved
        int i = pos / 9, j = pos % 9;
        if (board[i][j] != '.') return helper(board, pos + 1);        // skip givens

        int used = rows[i] | cols[j] | boxes[box(i, j)];
        for (int d = 0; d < 9; ++d) {
            int bit = 1 << d;
            if (used & bit) continue;                                 // O(1) legality test

            board[i][j] = '1' + d;                                    // choose
            rows[i] |= bit; cols[j] |= bit; boxes[box(i, j)] |= bit;

            if (helper(board, pos + 1)) return true;                  // explore (no undo on success)

            board[i][j] = '.';                                        // un-choose — all four
            rows[i] ^= bit; cols[j] ^= bit; boxes[box(i, j)] ^= bit;
        }
        return false;                                                 // nothing fits ⇒ dead branch
    }
public:
    void solveSudoku(vector<vector<char>>& board) {
        for (int i = 0; i < 9; ++i)                                   // seed masks from the givens
            for (int j = 0; j < 9; ++j)
                if (board[i][j] != '.') {
                    int bit = 1 << (board[i][j] - '1');
                    rows[i] |= bit; cols[j] |= bit; boxes[box(i, j)] |= bit;
                }
        helper(board, 0);
    }
};
```
**TC:** **O(9^m)** where `m` = number of empty cells (≤ 81) — branching ≤ 9, depth `m`, and with the masks each node is **O(1)** instead of O(27). The bound is wildly pessimistic; pruning makes real boards finish in microseconds. **SC:** **O(m)** recursion depth (≤ 81) + **O(1)** for the 27 ints; the board is mutated in place, so no output space.
**Say it as:** "the search space is 9^m, but the constraint check is what actually decides the runtime — so I'd make it O(1) with three bitmasks, and if that weren't enough I'd add **most-constrained-variable** ordering, which collapses the branching factor rather than the per-node cost."

## My Solution
```cpp
class Solution {
    bool safe(int row, int col, vector<vector<char>>&board, char ch) {
        for (int i = 0; i < 9; i++) {
            if (board[row][i] == ch || board[i][col] == ch) return false;
        }

        int subRow = (row / 3) * 3;
        int subCol = (col / 3) * 3;

        for (int i = subRow; i < subRow + 3; i++) {
            for (int j = subCol; j < subCol + 3; j++) {
                if (board[i][j] == ch) return false;
            }
        }
        return true;
    }
    bool helper(vector<vector<char>>& board) {
        for (int i = 0; i < 9; i++) {
            for (int j = 0; j < 9; j++) {
                if (board[i][j] == '.') {
                    for (char num = '1'; num <= '9'; num++) {
                        if (safe(i, j, board, num)) {
                            board[i][j] = num;
                            if (helper(board)) return true;
                            board[i][j] = '.';
                        }
                    }
                    // if no one match return false;
                    return false;
                }
            }
        }
        return true;
    }
public:
    void solveSudoku(vector<vector<char>>& board) {
        helper(board);
    }
};
```
**Correct — accepted, and it lands every structural decision that this problem is actually testing.** The `return false` is **inside** the empty-cell branch (the trap above). `return true` fires only after both scan loops complete with no `'.'` found — an implicit but valid base case. Success propagates up **without** undoing, failure undoes exactly one cell. `safe()` folds the row and column scan into one loop, and `(row/3)*3, (col/3)*3` is the correct box origin. The helper returns `bool` rather than `void`, which is the thing that makes the whole "dead branch" signal possible.

**Refinement 1 — you rescan the grid from (0,0) on every call.** Each frame walks from the top-left looking for the first `'.'`, re-examining every cell an ancestor already filled — O(81) of pure waste per node. Thread a flat position instead and the base case becomes explicit:
```cpp
bool helper(vector<vector<char>>& board, int pos) {
    if (pos == 81) return true;
    int i = pos / 9, j = pos % 9;
    if (board[i][j] != '.') return helper(board, pos + 1);
    ...
}
```

**Refinement 2 — make `safe()` O(1) with three bitmasks (this is *the* expected follow-up).** Your check costs 9 + 9 = 18 comparisons for row/col plus 9 for the box, repeated for up to 9 candidates at every node. Keep `rows[9] / cols[9] / boxes[9]` as int masks, prefill from the givens, then legality is one `(rows[i] | cols[j] | boxes[b]) & bit` test — see the canonical code. **The trap it introduces:** the undo must reset **all three masks *and* the board cell**; forgetting one leaks a phantom constraint into sibling branches and the solver reports an unsolvable board.

**Refinement 3 — MRV (most-constrained-variable) ordering, if pushed further.** Instead of the *first* empty cell, pick the empty cell with the **fewest** legal candidates: `__builtin_popcount(~(rows[i] | cols[j] | boxes[b]) & 0x1FF)`. Costs O(81) to select, but a cell with a single candidate has branching factor **1** — it's forced, not guessed. This is what separates "solves easy boards" from "solves adversarial boards instantly". Worth **naming out loud** even if you don't write it.

**Refinement 4 — nits.** `board` is threaded through every frame as a parameter; making it (and the masks) members removes the noise. `char num = '1'; num <= '9'` is fine, but iterating `int d = 0..8` pairs more naturally with `1 << d`.

## Other Approaches
- **Brute force — fill all `m` empty cells with every combination, then validate** *(name it, then reject it)* — **O(9^m · 81)** / **O(m)**. Identical exponent to the backtracking but with **zero pruning**: a board whose first two cells already conflict still enumerates all 9^(m−2) completions beneath them. The backtracking's entire value is rejecting at depth 2 instead of at the leaf. This is the same brute-vs-prune contrast as [[9-131-palindrome-partitioning|131]]'s bitmask enumeration.
- **Backtracking with an on-the-fly O(27) `safe()` scan** *(the natural first answer — yours)* — **O(9^m · 27)** / **O(m)**. Completely acceptable; the honest quote includes the 27, not just 9^m.
- **Backtracking + bitmask constraints** *(canonical / what to write)* — **O(9^m)** with **O(1)** per check / **O(m)** stack + O(1) masks. Three ints per constraint family, undo all three.
- **Backtracking + bitmask + MRV heuristic** *(optimal in practice)* — same worst-case bound, but the branching factor collapses toward 1 on constrained boards. The realistic answer to "make it faster on hard puzzles".
- **Constraint propagation (naked singles / hidden singles) before each guess** — repeatedly fill any cell with exactly one candidate, and any digit with exactly one home in a row/col/box, until nothing changes; only then guess. Peter Norvig's classic; solves most published puzzles with **no search at all**. Mention as the "how would you make it production-grade" answer.
- **Dancing Links / Algorithm X (exact cover)** — model Sudoku as an exact-cover matrix (729 rows × 324 columns) and run Knuth's DLX. The *theoretically* right answer and the one that generalises to N×N; **far too long to write in an interview** — name it, explain the reduction in one sentence, and move on.
- **Ask only "is this board valid?" instead ⇒ stop searching.** That's **LC 36 Valid Sudoku**: one pass with the same three bitmask families, **O(81)** / **O(1)**, no recursion. The moment the question is "validate" rather than "complete", the backtracking family is the wrong tool — same fork as [[9-131-palindrome-partitioning|131]] → LC 132.

## Pitfalls
- **`return false` placed after the scan loops instead of inside the `'.'` branch** — the solver skips the unsolvable cell, keeps scanning, and can `return true` on a board that still has holes. **The #1 bug in this problem.**
- **Making `helper` return `void`** — with no success/failure signal you can't distinguish "solved" from "dead end", so you can never stop or undo correctly. The `bool` return *is* the algorithm.
- **Undoing after a successful recursion** — `if (helper(...)) return true;` must return **before** the reset. Resetting unconditionally erases the solution you just found and hands back the original board.
- **Forgetting the undo on the failing path** — the wrong digit stays and poisons every sibling branch (the pattern's universal `pop_back` bug, in grid form).
- **With bitmasks: undoing only some of the three masks**, or the masks but not `board[i][j]`. A leaked bit is a phantom constraint ⇒ a solvable board reports unsolvable. Undo is `board` + `rows` + `cols` + `boxes`, always all four.
- **Box origin `row/3` instead of `(row/3)*3`** — collapses all nine boxes onto the top-left three rows; silently accepts illegal boards.
- **Box index `(i/3) + (j/3)`** instead of **`(i/3)*3 + j/3`** — collides boxes (e.g. box (0,2) and (2,0) both map to 2).
- **Checking `safe()` after writing the digit** — the cell now contains `ch`, so the row/col scan finds it and always returns false.
- **`1 << (num - '0')` instead of `1 << (num - '1')`** — off-by-one on the bit, wastes bit 0 and can shift a 9 into bit 9 (harmless but confusing when you `popcount` for MRV).
- **Quoting the complexity as O(81!)** or plain O(9⁸¹) — it's **O(9^m)** over the *empty* cells, and the pruning means the bound bears no relation to the observed runtime. Say both.
- **Inherited from the pattern:** searching for *all* solutions when the problem guarantees one — stop at the first `true`.
