# 8. 79. Word Search (LC 79) — Medium
🔗 [Open on LeetCode](https://leetcode.com/problems/word-search/)

**Pattern:** Backtracking — **grid DFS with an in-path visited set**; the first *constraint-satisfaction* problem of the folder (prune on invalidity, not on a `start` index)
**Trigger:** "does **word** exist in the **grid**, built from **4-directionally adjacent** cells, **same cell may not be reused**" → try **every cell as a start**, DFS matching `word[idx]`, mark the cell **on the path**, and **un-mark on the way out**. Not "return all" — just `true`/`false`, so return up the stack the instant a match completes.

## Problem (1-liner)
Given an `m × n` char grid and a string `word`, return `true` if `word` can be spelled by walking horizontally/vertically between adjacent cells, **never reusing a cell within the same path**.
**Examples:** `board = [["A","B","C","E"],["S","F","C","S"],["A","D","E","E"]]` · `"ABCCED" → true` · `"SEE" → true` · `"ABCB" → false` (the second `B` would have to reuse the first).
**Constraints:** `1 ≤ m, n ≤ 6` · `1 ≤ word.length ≤ 15` · letters only (mixed case).
**Edge case:** **`word.length == 1`** — the answer is just "does any cell equal `word[0]`"; the recursion must succeed *before* taking a single step. Also `word.size() > m*n` ⇒ impossible by counting.

## Idea (1-liner)
The grid isn't a tree — a cell can be re-entered from a different path — so **the "un-choose" step is what makes it a tree again**: mark the cell as on-path, explore the 4 neighbours, then **restore it** so a *different* start or a *different* branch may legally use it. Reuse is forbidden **within one path**, not globally.

## Approach
1. **Try every cell as an origin.** `board[i][j] == word[0]` ⇒ launch a DFS that has already consumed index 0, i.e. `helper(i, j, 1)`.
2. **Base case first:** `if (idx == word.size()) return true;` — placed **above** the marking, so a length-1 word returns immediately.
3. **Choose:** mark the current cell (`visited[r][c] = 1`, or overwrite with `'#'`).
4. **Explore:** for each of the 4 directions, keep only neighbours that are **in bounds**, **unvisited**, and **match `word[idx]`**. Recurse; if any returns `true`, **propagate `true` immediately** — no need to un-mark, you're leaving for good.
5. **Un-choose:** on failure, restore the cell and return `false`.

> **Load-bearing insight:** every other note in this folder builds a *combinatorial* object and records at a node or a leaf. Here the search space is a **graph**, and the only reason it terminates is the visited marking — without it, `A → B → A → B …` recurses forever. The subtlety that separates a correct solution from a plausible one is **where the restore happens**: reset on the failing path only. Un-marking after a successful branch is harmless *for this problem* (you return out immediately), but forgetting to un-mark on failure poisons every later start — the grid slowly fills with fake obstacles and you get false negatives.

## Code (clean canonical)
```cpp
class Solution {
    static constexpr int dr[4] = {0, 0, -1, 1};
    static constexpr int dc[4] = {-1, 1, 0, 0};
    int rows, cols;

    bool helper(int r, int c, int idx, vector<vector<char>>& board, const string& word) {
        if (idx == (int)word.size()) return true;

        char cur = board[r][c];
        board[r][c] = '#';                       // choose (mark on-path)

        for (int k = 0; k < 4; ++k) {
            int nr = r + dr[k], nc = c + dc[k];
            if (nr >= 0 && nr < rows && nc >= 0 && nc < cols &&
                board[nr][nc] == word[idx]) {    // '#' can never match a letter ⇒ visited check is free
                if (helper(nr, nc, idx + 1, board, word)) return true;
            }
        }

        board[r][c] = cur;                       // un-choose (restore)
        return false;
    }
public:
    bool exist(vector<vector<char>>& board, string word) {
        rows = board.size(); cols = board[0].size();
        if ((int)word.size() > rows * cols) return false;

        for (int i = 0; i < rows; ++i)
            for (int j = 0; j < cols; ++j)
                if (board[i][j] == word[0] && helper(i, j, 1, board, word))
                    return true;
        return false;
    }
};
```
**TC:** **O(m·n·3^L)** — `m·n` starting cells; after the first step you never step back onto the parent, so the branching factor is **3**, not 4, over `L = word.length` steps. **SC:** **O(L)** recursion stack (the in-place marking costs **no** extra space).
**Say it as:** "m·n starts × 3^L paths; with `m,n ≤ 6` and `L ≤ 15` the pruning is what actually keeps it alive."

## My Solution
```cpp
class Solution {
    vector<int>dr = {0, 0, -1, 1};
    vector<int>dc = {-1, 1, 0, 0};

    bool helper(int row, int col, int idx, vector<vector<char>>& board, string &word, vector<vector<int>>&visited) {
        int rows = board.size(), cols = board[0].size();
        if (idx == word.size()) return true;

        visited[row][col] = 1;

        for (int i = 0; i < 4; i++) {
            int newRow = row + dr[i], newCol = col + dc[i];
            if (newRow >= 0 && newCol >= 0 && newRow < rows && newCol < cols &&
            board[newRow][newCol] == word[idx] &&  !visited[newRow][newCol]) {
                if (helper(newRow, newCol, idx + 1, board, word, visited)) return true;
            }
        }
        visited[row][col] = 0;
        return false;
    }
public:
    bool exist(vector<vector<char>>& board, string word) {
        int rows = board.size(), cols = board[0].size();
        vector<vector<int>>visited(rows, vector<int>(cols, 0));

        for (int i = 0; i < rows; i++) {
            for (int j = 0; j < cols; j++) {
                if (board[i][j] == word[0] &&
                helper(i, j, 1, board, word, visited)) return true;
            }
        }
        return false;
    }
};
```
**Correct — accepted, and it gets both hard parts right.** The base case sits **above** `visited[row][col] = 1`, so `word.size() == 1` returns `true` without stepping (the most common failure of this problem). And every marked cell is unmarked on the `false` path, so `visited` is clean between the `(i, j)` starts — the second most common failure. On the `true` path the array is left dirty, which is harmless because you return straight out of `exist`.

**Refinement 1 — drop `visited` entirely, mark in place.** Saves the O(m·n) array *and* one clause of the guard:
```cpp
char cur = board[r][c];
board[r][c] = '#';                 // instead of visited[r][c] = 1
...                                // guard loses "&& !visited[nr][nc]"
board[r][c] = cur;                 // instead of visited[r][c] = 0
```
`'#'` isn't a letter, so `board[nr][nc] == word[idx]` already excludes on-path cells. This is the version interviewers expect. (Restore `cur`, not `word[idx-1]`-by-assumption — same value, but `cur` can't be wrong.)

**Refinement 2 — hoist `rows`/`cols`.** You recompute `board.size()` / `board[0].size()` in **every** recursive frame. Make them members set once in `exist`.

**Refinement 3 — `static constexpr int[4]` for `dr`/`dc`.** `vector<int>` members mean two heap allocations per `Solution` construction for four constants.

**Refinement 4 — `idx == word.size()` compares `int` to `size_t`.** Cast, or make `idx` a `size_t`. Same class of warning as in [[7-17-letter-combinations-of-a-phone-number|17]].

## Other Approaches
- **Enumerate all paths, then string-match** *(brute)* — generate every simple path of length `L` from every cell and compare. Same asymptotics but materialises the strings: **O(m·n·3^L·L)** time and **O(L)**× the memory traffic. Only worth naming to reject.
- **Backtracking with a `visited` matrix** *(the natural first answer)* — **O(m·n·3^L)** / **O(m·n + L)**. Fully correct; reach for it when the board is `const` / shared across threads and you *can't* mutate it.
- **Backtracking with in-place `'#'` marking** *(canonical)* — **O(m·n·3^L)** / **O(L)**. The default. Mention that it mutates the input and is restored on unwind.
- **Pruned backtracking** *(the stated follow-up — "search pruning … larger board")*, two independent wins:
  1. **Frequency pre-check** — if any letter of `word` appears more times in `word` than in `board`, answer `false` in **O(m·n + L)** without a single recursive call.
  2. **Search the rarer end first** — the branching cost is dominated by how many cells match the **first** character. If `word.back()` is scarcer in the board than `word.front()`, **reverse `word`** before searching; the answer is identical and the tree can shrink by orders of magnitude.
```cpp
unordered_map<char,int> cnt;
for (auto& row : board) for (char ch : row) cnt[ch]++;
for (char ch : word) if (--cnt[ch] < 0) return false;          // 1. impossible by count
// 2. start from whichever end is rarer on the board
if (cntOf(word.back()) < cntOf(word.front())) reverse(word.begin(), word.end());
```
- **Trie + backtracking** — pointless for **one** word, mandatory for **many**: that's **Word Search II** (LC 212), where you walk all words down a shared trie in a single DFS instead of re-running `exist` per word. The tell is "given a **list** of words".

## Pitfalls
- **Marking before the base case** — `visited[r][c] = 1` above `if (idx == word.size()) return true;` still works, but the mirror bug (checking `idx == word.size() - 1` and requiring a step) breaks **every length-1 word**. Decide your index convention once: here `idx` = *the character we still need to match*, and `exist` enters at `1` because the origin already matched `word[0]`.
- **Not un-marking on failure** — the #1 correctness bug. The grid accumulates phantom obstacles and later start cells report false negatives. `"ABCCED"` may pass while `"SEE"` mysteriously fails.
- **Sharing `visited` globally instead of per-path** — same bug in a different costume. Reuse is banned **within one path**, not across the whole search.
- **Forgetting the origin's own match** — calling `helper(i, j, 0)` from `exist` re-checks `word[0]` against the neighbours, not the cell itself, and silently matches the wrong strings.
- **Diagonal neighbours** — the problem says *horizontally or vertically*. An 8-direction `dr/dc` table is a classic copy-paste import from a flood-fill problem.
- **Restoring the wrong character** in the in-place version — save `board[r][c]` into a local before overwriting; don't reconstruct it from `word`.
- **Quoting O(m·n·4^L)** — technically an upper bound, but **3^L** is the right answer and shows you noticed you never step back onto the parent.
- **Inherited from the pattern:** missing the un-choose; and note this problem *breaks* the folder's habits — there is **no `start` index**, **no dedup guard**, and **nothing is recorded**, because the output is a single `bool`.
