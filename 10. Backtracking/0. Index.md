# Backtracking — Index

60-second whole-pattern recall. Read the **Trigger** column and try to recall the **Idea** before peeking.

**Core skeleton:** **choose → explore → un-choose.** Carry one shared buffer `temp`; loop `i` from `start`, `push_back` the choice, recurse with **`i + 1`** (or `i` if reuse is allowed), then **`pop_back()`**. Where you *record* decides the shape: record at **every node** → subsets/combinations; record at **leaves** (`index == n` / `temp.size() == n`) → permutations/full-length answers. Complexity is dominated by the output: **O(#answers × length)**, auxiliary **O(n)** for the recursion stack. Duplicates in the input ⇒ **sort + skip equal siblings** (`i > start && nums[i] == nums[i-1]`).

```cpp
void bt(int start) {
    ans.push_back(temp);                    // record (every node here; move to a base case for permutations)
    for (int i = start; i < n; ++i) {
        temp.push_back(nums[i]);            // choose
        bt(i + 1);                          // explore
        temp.pop_back();                    // un-choose
    }
}
```

## When to reach for Backtracking
1. **"Return all …"** — subsets, permutations, combinations, partitions, paths. Output is exponential, so enumeration is the *intended* solution.
2. **Constraint satisfaction** — N-Queens, Sudoku, Word Search: build a partial solution, abandon (prune) the branch the moment it's invalid.
3. **Counting/existence with heavy pruning** — when a greedy/DP formulation doesn't exist and the branching factor collapses fast.
4. **Not** when only the *count* or the *best* answer is wanted and states overlap — that's DP/memoisation, not enumeration.

## Common Pitfalls Across the Pattern
- **Forgetting to un-choose** (`pop_back()` / resetting `used[i] = false`) — state leaks into sibling branches. The #1 bug.
- **`i + 1` vs `start + 1` vs `i`** — `i + 1` = each element once (combinations); `i` = reuse allowed (Combination Sum); `start + 1` is almost always a bug.
- **Recording in the wrong place** — every node (subsets) vs only at a base case (permutations/full-length). Silently returns the wrong family of answers.
- **Deduping with a `set`** instead of **sort + skip equal siblings** — works but hides the actual pattern and costs an extra log factor.
- **Passing the buffer by value** — correct but copies at every frame; pass by reference and backtrack.
- **Recursion depth** — depth is n (or the path length); fine for the typical `n ≤ 20`, but say it out loud when asked for space complexity: auxiliary O(n), output separate.
