# 2. 90. Subsets II (LC 90) — Medium
🔗 [Open on LeetCode](https://leetcode.com/problems/subsets-ii/)

**Pattern:** Backtracking — **power set with duplicates**; this is where the pattern's universal dedup rule (**sort + skip equal siblings**) is born
**Trigger:** "all subsets, but the input **may contain duplicates**, and the output must contain **no duplicate subsets**" → [[1-78-subsets|Subsets]] + one guard line. **Sort first** (makes copies adjacent), then at each level skip a value you've already branched on **at that same level**: `if (i > start && nums[i] == nums[i-1]) continue;`. Any "duplicates in input, distinct combinations out" problem reuses this exact line.

## Problem (1-liner)
Given `nums` that **may contain duplicates**, return all possible subsets (the power set) with **no duplicate subsets**. Any order.
**Examples:** `[1,2,2] → [[],[1],[1,2],[1,2,2],[2],[2,2]]` (**6**, not 2³=8 — `[2]` and `[1,2]` would each appear twice) · `[0] → [[],[0]]`.
**Constraints:** `1 ≤ n ≤ 10`, `-10 ≤ nums[i] ≤ 10`. Input is **not sorted** (`[4,4,4,1,4]` is legal) and n ≥ 1.
**Edge case:** `[]` is still part of the answer, and `[2,2]` is a *legitimate* subset — duplicate **elements** are allowed, only duplicate **subsets** are banned.

## Idea (1-liner)
A subset here is a **multiset**, and two different *choices of copies* can produce the same multiset — picking the 1st `2` vs the 2nd `2` both give `[2]`. Kill the ambiguity by fixing a **canonical choice**: among equal values, always take a **prefix of the run**. Sorting puts equal values adjacent, which turns that global rule into a one-line local check — and the answer count drops from 2ⁿ to **Π(count(v) + 1)** over distinct values (`[1,2,2]` → 2×3 = 6 ✅).

## Approach
1. **`sort(nums)`** — mandatory; `nums[i] == nums[i-1]` only detects duplicates when copies are adjacent.
2. `helper(start)`: record `temp` (every node is a valid subset, same as 78).
3. Loop `i` from `start` to `n-1`: **`if (i > start && nums[i] == nums[i-1]) continue;`** — this value was already branched on at this level.
4. Otherwise `push_back` → `helper(i + 1)` → `pop_back()`.

> **Load-bearing insight:** **`i > start`, not `i > 0`.** `start` marks the first choice *at this depth*, so the **first** copy of a run is always allowed and only its equal **siblings** are skipped. Write `i > 0` and the second `2` gets rejected even one level deeper — you lose `[2,2]` and every subset containing repeated values.

## Code (clean canonical)
```cpp
class Solution {
    vector<vector<int>> ans;
    vector<int> temp;

    void helper(int start, vector<int>& nums) {
        ans.push_back(temp);                                    // every node is a subset
        for (int i = start; i < nums.size(); ++i) {
            if (i > start && nums[i] == nums[i - 1]) continue;   // skip equal SIBLINGS
            temp.push_back(nums[i]);                            // choose
            helper(i + 1, nums);                                // explore
            temp.pop_back();                                    // un-choose
        }
    }
public:
    vector<vector<int>> subsetsWithDup(vector<int>& nums) {
        sort(nums.begin(), nums.end());                         // mandatory
        helper(0, nums);
        return ans;
    }
};
```
**TC:** O(2ⁿ · n) — bounded by the power set (fewer in practice: Π(cnt+1) subsets), each copied at cost n. **SC:** O(n) auxiliary + O(n log n) sort; output O(2ⁿ · n).
**Why this shape:** it is [[1-78-subsets|Subsets]] plus exactly one line, and that same line is the fix for Combination Sum II and Permutations II. Memorise the guard, not four separate solutions.

## My Solution
```cpp
class Solution {
    vector<vector<int>> ans;
    vector<int> temp;

    void helper(int index, vector<int>& nums) {
        if (index == nums.size()) { ans.push_back(temp); return; }

        // Pick the current element
        temp.push_back(nums[index]);
        helper(index + 1, nums);
        temp.pop_back();

        // Not pick → skip ALL copies of nums[index]
        int j = index + 1;
        while (j < (int)nums.size() && nums[j] == nums[j - 1]) j++;
        helper(j, nums);
    }
public:
    vector<vector<int>> subsetsWithDup(vector<int>& nums) {
        sort(nums.begin(), nums.end());  // Mandatory
        helper(0, nums);
        return ans;
    }
};
```
**Correct** — same O(2ⁿ · n) / O(n). This is the **pick/not-pick** shape, and its dedup rule is genuinely *different* from the loop version: **if you decline an element you must decline its entire run.** Otherwise "skip the 1st `2`, take the 2nd" and "take the 1st `2`, skip the 2nd" both emit `[2]`. Trace `[1,2,2]` → `[1,2,2] [1,2] [1] [2,2] [2] []` = 6 ✅.
**Notes:** the run-scan `nums[j] == nums[j-1]` is equivalent to `nums[j] == nums[index]` on a sorted array (the chain of consecutive equalities can only start at `index`), but the `nums[index]` form states the intent — "skip copies of *the element I just declined*" — and doesn't rely on the reader reconstructing the chain. Also: `index == nums.size()` compares `int` to unsigned `size_t`; cast for a clean build. **Trap you already hit:** `continue` here is a **compile error** — there's no loop in this shape; and swapping it for `return` would kill the whole branch and lose `[2,2]`.
**Refinement:** prefer the loop template as your default — the pick/not-pick dedup is a second rule to memorise, while `i > start && nums[i] == nums[i-1]` transfers unchanged to three sibling problems.

## Other Approaches
- **Generate all 2ⁿ, then dedupe** *(brute)* — run [[1-78-subsets|Subsets]] unchanged, sort each subset, drop it into a `set<vector<int>>`. **O(2ⁿ · n log n)** time, **O(2ⁿ · n)** space. Passes at `n ≤ 10`, but it's the "I didn't spot the pattern" answer — say it in one sentence, then give the guard.
- **Sort + skip equal siblings** *(canonical)* — **O(2ⁿ · n)** / **O(n)**. The default. Zero wasted branches, and it's the transferable rule.
- **Pick/not-pick + skip the whole run** *(equivalent)* — the solution above. **O(2ⁿ · n)** / **O(n)**. Use it when you're already narrating the binary decision tree.
- **Frequency-map cascading** *(iterative, no recursion — the "how would you scale it?" answer)* — count each distinct value, then for value `v` with count `c` extend every existing subset by **0, 1, … c** copies. Generates **Π(cnt+1)** subsets with **no duplicates ever created**, so nothing is filtered:
  ```cpp
  map<int,int> freq;
  for (int x : nums) freq[x]++;
  vector<vector<int>> ans = {{}};
  for (auto& [v, c] : freq) {
      int sz = ans.size();                        // snapshot BEFORE growing
      for (int i = 0; i < sz; ++i)
          for (int k = 1; k <= c; ++k) {
              ans.push_back(ans[i]);
              ans.back().insert(ans.back().end(), k, v);
          }
  }
  ```
  **O(answers · n)** time, **O(1)** auxiliary (no call stack). Cleanest framing of *why* the count is Π(cnt+1).
- **Bitmask** *(regression here)* — the 78 trick still enumerates 2ⁿ masks, but distinct masks now yield identical multisets, so you'd need a `set` on top. Strictly worse than the guard; mention only to dismiss it.

## Pitfalls
- **Forgetting `sort`** — the single fatal bug. `nums[i] == nums[i-1]` silently never fires on `[4,4,4,1,4]` and you emit duplicates. Sorting is what makes the local check valid.
- **`i > 0` instead of `i > start`** — rejects a duplicate that lives one level *deeper*, so `[2,2]`, `[1,2,2]`, `[2,2,2]` all vanish. The most common wrong fix.
- **`continue` in the pick/not-pick shape** — compile error (no enclosing loop); `return` "fixes" the build and silently prunes valid branches. The two templates have **different** dedup rules — don't cross-breed them.
- **Skipping only one duplicate in the not-pick branch** (`helper(index + 2)`) — with 3+ copies you still emit duplicates. Skip the whole **run**.
- **Reaching for `set<vector<int>>` as the real solution** — it works but hides the pattern and costs an extra log factor; it's the brute-force fallback, not the answer.
- **Assuming the output is 2ⁿ** — it's **Π(count(v) + 1)**. `[1,2,2]` → 6, not 8. Interviewers ask for this count.
- **Inherited from 78:** missing `pop_back()`; recording only at leaves in the loop template; `[]` is a valid answer.
