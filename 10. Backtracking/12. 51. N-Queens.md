# 12. 51. N-Queens (LC 51) — Hard
🔗 [Open on LeetCode](https://leetcode.com/problems/n-queens/)

**Pattern:** Backtracking — **constraint satisfaction that *collects*:** the pruning machinery of [[11-37-sudoku-solver|37]] / [[8-79-word-search|79]], but the recursion returns `void` and pushes every complete board, so there is **no early exit**
**Trigger:** "place `n` queens on an `n × n` board so **no two attack each other**, return **all distinct** configurations" → recurse **one row at a time** (`helper(row)`), loop the **column**, keep it only if that column and both diagonals are free, and record at **`row == n`**.

## Problem (1-liner)
Place `n` queens on an `n × n` board so that no two share a row, column, or diagonal; return **every** distinct board as a vector of strings using `'Q'` and `'.'`.
**Examples:** `n = 4 → [[".Q..","...Q","Q...","..Q."], ["..Q.","Q...","...Q",".Q.."]]` · `n = 1 → [["Q"]]`
**Constraints:** `1 ≤ n ≤ 9`.
**Edge case:** **`n = 2` and `n = 3` return `[]`** — genuinely unsolvable, and the only "empty result" cases that exist. `n = 1` returns one board. Solution counts grow ferociously and unpredictably: `1, 0, 0, 2, 10, 4, 40, 92, 352` for `n = 1..9` — there is **no formula**, which is exactly why enumeration is the intended solution.

## Idea (1-liner)
Two queens can never share a row, so **fix one queen per row up front** — the answer is then just "which column for each row?", i.e. a **permutation of columns** filtered by the diagonal test. That single observation collapses the search from `C(n², n)` placements to at most `n!`.

## Approach
1. `helper(row)` means: *rows `0 .. row-1` already hold one safe queen each; place the queen for `row`.*
2. **Base case:** `row == n` ⇒ every row is filled ⇒ `result.push_back(board)`. Record **only here** — a partial board isn't a solution.
3. **Choice loop:** `for (col = 0; col < n; ++col)` — the choice is *which column in this row*, never "which square on the board".
4. **Safety test:** the square is free iff no queen shares its **column**, its **↖ diagonal**, or its **↗ diagonal**. Scan **upward only** — rows below `row` are still empty.
5. **Choose → explore → un-choose:** `board[row][col] = 'Q'` → `helper(row + 1)` → `board[row][col] = '.'`.
6. **Never early-exit.** Unlike [[11-37-sudoku-solver|37]], you want *all* boards, so the helper returns `void` and every branch runs to completion.

> **Load-bearing insight:** two separate economies are doing the work, and interviewers probe both. **(a) One queen per row is structural** — it's encoded in the recursion signature, so a whole class of illegal boards is never generated, and you never need a "same row?" check. **(b) `safe()` looks only *upward*** (`i--` in every loop): rows `> row` are empty by construction, so checking downward is pure waste, and checking sideways in the current row is impossible by (a). The three tests you *do* need — column, ↖, ↗ — each have a **constant key**: `col`, `row + col`, and `row - col`. Both diagonal sums/differences are invariant along the diagonal, which is what turns an O(n) scan into an O(1) lookup.

## Code (clean canonical)
```cpp
class Solution {
    int n;
    vector<bool> cols, diag, anti;        // diag: row-col+n-1 (↘)   anti: row+col (↗)
    vector<string> board;
    vector<vector<string>> res;

    void helper(int row) {
        if (row == n) { res.push_back(board); return; }

        for (int col = 0; col < n; ++col) {
            int d = row - col + n - 1, a = row + col;
            if (cols[col] || diag[d] || anti[a]) continue;          // O(1) prune

            board[row][col] = 'Q';                                  // choose
            cols[col] = diag[d] = anti[a] = true;

            helper(row + 1);                                        // explore

            board[row][col] = '.';                                  // un-choose — all four
            cols[col] = diag[d] = anti[a] = false;
        }
    }
public:
    vector<vector<string>> solveNQueens(int N) {
        n = N;
        cols.assign(n, false);
        diag.assign(2 * n - 1, false);
        anti.assign(2 * n - 1, false);
        board.assign(n, string(n, '.'));

        helper(0);
        return res;
    }
};
```
**TC:** **O(n! · n)** — at most `n!` leaves (column permutations), O(n) candidates per node at O(1) each; add **O(n²)** per *solution* to copy the board strings. **SC:** **O(n²)** for the working board + **O(n)** for the three marker arrays and the recursion depth (output excluded).
**Say it as:** "one queen per row makes it a permutation search — n! upper bound, and the diagonals prune it far below that. The only thing I control is the **cost of the safety check**, which I make O(1) by keying on `col`, `row + col` and `row − col`."

## My Solution
```cpp
class Solution {
    bool safe(vector<string>&board, int row, int col) {
        // Check Left Diagonal
        int i = row, j = col;
        while (i >= 0 && j >= 0) {
            if (board[i][j] == 'Q') return false;
            i--, j--;
        }
        // check right diagonal
        i = row, j = col;
        while (i >= 0 && j < board.size()) {
            if (board[i][j] == 'Q') return false;
            i--, j++;
        } 
        // Check in the straight up
        i = row;
        while(i >= 0) {
            if (board[i][col] == 'Q') return false;
            i--;
        }
        return true;
    }
    void helper(int row, vector<string>&board, vector<vector<string>>&result) {
        if (row == board.size()) {
            result.push_back(board);
            return;
        }

        for (int i = 0; i < board.size(); i++) {
            if (safe(board, row, i)) {
                board[row][i] = 'Q';
                helper(row + 1, board, result);
                board[row][i] = '.';
            }
        }
    }
public:
    vector<vector<string>> solveNQueens(int n) {
        vector<vector<string>>result;
        vector<string>board(n, string(n, '.'));

        helper(0, board, result);

        return result;
    }
};
```
**Correct — accepted, and it lands both economies that matter.** One queen per row is encoded in the recursion (`helper(row + 1)`, loop over columns), so there is no row check and no `C(n², n)` blowup. `safe()` scans **upward only** in all three directions — the detail most people get wrong by also sweeping down or sideways. Recording happens only at `row == board.size()`, the un-choose is present on every branch, and there's correctly **no early exit** (you want all boards, not one). Starting each scan at `(row, col)` itself instead of one step up is harmless — that cell is `'.'` when the check runs.

**Refinement 1 — make `safe()` O(1) (the expected follow-up).** You rescan up to `3n` cells per candidate, i.e. O(n²) work per node. Every attacked line has a constant key: **column → `col`**, **↘ diagonal → `row - col + n - 1`** (the `+ n - 1` only shifts it non-negative), **↗ diagonal → `row + col`**. Three `vector<bool>`s of size `n`, `2n-1`, `2n-1` turn the test into three array reads — see the canonical code. **The trap it introduces:** the undo must clear **all three flags *and* the board cell**; leaving one set leaves a phantom attack line that silently drops valid solutions (same class of bug as the mask undo in [[11-37-sudoku-solver|37]]).

**Refinement 2 — the elegant variant worth naming: bitmasks.** Carry the three constraints as `int`s and let the shifts do the diagonal arithmetic:
```cpp
int avail = ~(cols | d1 | d2) & ((1 << n) - 1);
while (avail) {
    int bit = avail & -avail;                       // lowest set bit = next free column
    avail -= bit;
    helper(row + 1, cols | bit, (d1 | bit) << 1, (d2 | bit) >> 1);
}
```
A diagonal threat shifts one column per row, so `<< 1` / `>> 1` *is* the propagation — no index arithmetic, no explicit undo (the state is passed by value). O(1) auxiliary beyond the stack.

**Refinement 3 — carry `vector<int> pos` (column per row), build the strings only at the leaf.** You keep a full O(n²) grid alive through the entire search purely so `safe()` can read it. With Refinement 1, `safe()` never touches the board, so the board becomes **output-only** — auxiliary space drops to O(n).

**Refinement 4 — nits.** `i < board.size()` and `row == board.size()` compare `int` to `size_t` (sign-compare warning) — hoist `int n = board.size();`. Same nit as in [[8-79-word-search|79]] / [[9-131-palindrome-partitioning|131]]. Also `i--, j--` uses the comma operator where two statements read clearer.

## Other Approaches
- **Brute force — all `C(n², n)` placements, validate each** *(name it, then reject it)* — for `n = 8` that's `C(64,8) ≈ 4.4 × 10⁹` boards, each O(n²) to check. **O(C(n²,n) · n²)**. Hopeless, and the fix is one observation: two queens can't share a row.
- **Permutation brute force — try all `n!` column permutations, then check diagonals** — **O(n! · n)** / **O(n)**. Same exponent as the backtracking and it already encodes "one per row + one per column", but it has **no pruning**: a diagonal conflict between rows 0 and 1 still enumerates all `(n−2)!` completions beneath it. The backtracking kills that subtree at depth 2. Good to state as the bridge between brute force and the real answer.
- **Backtracking with an on-the-fly O(n) scan** *(the natural first answer — yours)* — **O(n! · n²)** / **O(n²)**. Perfectly acceptable at `n ≤ 9`; just quote the extra `n` honestly rather than borrowing the O(1)-check bound.
- **Backtracking + `cols` / `row+col` / `row−col` marker arrays** *(canonical — what to write)* — **O(n! · n)** / **O(n)** auxiliary. The O(1) prune is the whole delta.
- **Backtracking + bitmasks** *(optimal, and the "can you do it without arrays?" answer)* — same TC, **O(1)** auxiliary beyond the recursion stack, and no explicit un-choose since state is passed by value.
- **Mirror-symmetry pruning** — restrict row 0 to columns `[0, n/2)` and reflect each solution; halves the search. Fiddly for odd `n` (the centre column has no mirror) and it scrambles output order. **Say it, don't write it.**
- **Ask for the *count* instead ⇒ stop building boards.** That's **LC 52 N-Queens II**: identical search returning an `int`, no board at all, so the bitmask version is **O(1)** auxiliary. And if they ask for *one* solution rather than all, you get an early exit back and the helper returns `bool` — i.e. it becomes [[11-37-sudoku-solver|37]]'s shape.

## Pitfalls
- **Scanning downward or sideways in `safe()`** — rows below `row` are empty by construction and the current row can't hold another queen, so it's wasted work (and sideways checks tempt you into a wrong "row" test). Upward only: `i--` in all three loops.
- **Checking only one diagonal** — you need both **↖** and **↗**. Missing `↗` still returns plausible-looking boards and passes `n = 1`; it breaks at `n = 4`.
- **Diagonal key sign** — `row - col` ranges `[-(n-1), n-1]`, so index it as **`row - col + n - 1`** into an array of size `2n - 1`. Forgetting the shift is an out-of-bounds read, not a wrong answer, so it may "work" in debug and crash later.
- **Sizing the diagonal arrays `n` instead of `2n - 1`** — silently collides distinct diagonals and loses solutions.
- **With markers: undoing only some of the flags** (or the flags but not `board[row][col]`) — a phantom attack line leaks into sibling branches and valid boards vanish. Undo all four, always.
- **Early-exiting on the first solution** — this problem *collects*; the helper returns `void`. Returning `bool` here quietly gives you one board instead of 92. (Contrast [[11-37-sudoku-solver|37]], where early exit is *required*.)
- **Recording at every node** instead of at `row == n` — emits partial boards with empty rows.
- **Placing more than one queen per row** by looping over all `n²` squares — correct-but-catastrophic, and it reintroduces the row check you'd deleted.
- **Assuming the result is never empty** — `n = 2` and `n = 3` legitimately return `[]`.
- **Quoting flat O(n!)** — each solution costs O(n²) to materialise as strings, and an O(n) `safe()` adds another factor. Say which version you're pricing.
- **Inherited from the pattern:** missing the un-choose; passing the board by value (correct but copies at every frame).
