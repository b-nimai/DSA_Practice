# 1. 78. Subsets (LC 78) — Medium
🔗 [Open on LeetCode](https://leetcode.com/problems/subsets/)

**Pattern:** Backtracking — **subset generation (power set)**, the seed problem of the whole choose/explore/unchoose family
**Trigger:** "return **all** subsets / the power set, elements are **unique**, any order" → output size is **2ⁿ**, so the answer *is* exponential ⇒ enumerate by recursion. Two equivalent shapes: **pick / not-pick per index** (binary tree, 2ⁿ leaves) or the **loop-from-`start`** template (record at *every* node). `n ≤ 20` in a "give me all subsets" problem is the giveaway.

## Problem (1-liner)
Given `nums` of **unique** integers, return **all possible subsets** (the power set). No duplicate subsets; any order accepted.
**Examples:** `[1,2,3] → [[],[1],[2],[1,2],[3],[1,3],[2,3],[1,2,3]]` (8 = 2³) · `[0] → [[],[0]]`.
**Constraints:** `1 ≤ n ≤ 10`, `-10 ≤ nums[i] ≤ 10`, **all elements unique**. So `n ≥ 1` (never an empty array), 2ⁿ ≤ 1024, and **no dedup logic is needed** — uniqueness of input guarantees uniqueness of output.
**Edge case:** the **empty subset `[]` is part of the answer** — and so is the full array.

## Idea (1-liner)
Every subset is one **yes/no decision per element**, so the search space is a binary tree of depth `n` whose **2ⁿ leaves are exactly the 2ⁿ subsets**. Walk that tree carrying one shared `temp` buffer: push a choice, recurse, then `pop_back()` to restore state for the sibling branch. Because the input is unique, no two root-to-leaf paths produce the same set — the dedup problem simply doesn't exist here (that's [[2-90-subsets-ii|Subsets II]]).

## Approach
1. Keep one running buffer `temp` (the subset being built) and the result `ans`.
2. `helper(start)`: **record `temp` immediately** — every node of the recursion tree is itself a valid subset.
3. Loop `i` from `start` to `n-1`: `temp.push_back(nums[i])` → `helper(i + 1)` → `temp.pop_back()`.
4. Starting the loop at `start` (and recursing with `i + 1`) fixes a **left-to-right order**, so each subset is generated by exactly one path.

> **Load-bearing insight:** `i + 1`, **not** `start + 1`. Recursing with `start + 1` re-offers the elements you skipped in this loop iteration and blows up into duplicates/permutations. And the record happens **at every node**, not only at leaves — that is what makes the loop template emit all 2ⁿ subsets instead of just the full-length one.

## Code (clean canonical)
```cpp
class Solution {
    vector<vector<int>> ans;
    vector<int> temp;

    void helper(vector<int>& nums, int start) {
        ans.push_back(temp);                     // every node is a valid subset
        for (int i = start; i < nums.size(); ++i) {
            temp.push_back(nums[i]);             // choose
            helper(nums, i + 1);                 // explore (i+1, NOT start+1)
            temp.pop_back();                     // un-choose (backtrack)
        }
    }
public:
    vector<vector<int>> subsets(vector<int>& nums) {
        ans.reserve(1 << nums.size());
        helper(nums, 0);
        return ans;
    }
};
```
**TC:** O(2ⁿ · n) — 2ⁿ subsets, each copied into `ans` at avg cost n/2.  **SC:** O(n) auxiliary (recursion depth + `temp`); the output itself is O(2ⁿ · n).
**Why this shape is the one to memorise:** it's the workspace's backtracking template verbatim, and every sibling problem is a *one-line delta* from it (see the family map).

## My Solution
```cpp
class Solution {
    void helper(int index, int size, vector<vector<int>>& ans, vector<int>& nums, vector<int>& temp) {
        if (index == size) {
            ans.push_back(temp);
            return;
        }
        // Do Not pick the current element
        helper(index + 1, size, ans, nums, temp);
        // Pick the current element
        temp.push_back(nums[index]);
        helper(index + 1, size, ans, nums, temp);
        temp.pop_back();
    }
public:
    vector<vector<int>> subsets(vector<int>& nums) {
        vector<vector<int>> ans;
        vector<int> temp;
        int n = nums.size();
        helper(0, n, ans, nums, temp);
        return ans;
    }
};
```
**Correct** — same O(2ⁿ · n) / O(n). This is the **pick / not-pick** shape: the base case `index == size` fires once per root-to-leaf path, so all 2ⁿ leaves are recorded exactly once, and `push_back … recurse … pop_back` restores `temp` so nothing leaks between branches. Trace on `[1,2,3]` (not-pick explored first): `[] [3] [2] [2,3] [1] [1,3] [1,2] [1,2,3]` — all 8, and any order is accepted.
**Refinements:** hoist `nums`/`ans`/`temp` to members and drop the redundant `size` param (`nums.size()` already has it) — the signature collapses from 5 params to 1. Add `ans.reserve(1 << n)` to skip ~n reallocations. Worth knowing that the **loop template above generalises** to Subsets II / Combination Sum / Permutations with a one-line change, while pick/not-pick needs restructuring — prefer the loop shape as your default muscle memory.

## Other Approaches
- **Iterative cascading** *(no recursion, arguably the cleanest)* — seed `ans = {{}}`; for each `x` in `nums`, append `x` to a copy of **every subset already in `ans`** and add those back. Size doubles each round: 1 → 2 → 4 → … → 2ⁿ. **O(2ⁿ · n)** time, **O(1)** auxiliary.
  ```cpp
  vector<vector<int>> ans = {{}};
  for (int x : nums) {
      int sz = ans.size();                 // snapshot BEFORE growing
      for (int i = 0; i < sz; ++i) {
          ans.push_back(ans[i]);
          ans.back().push_back(x);
      }
  }
  ```
  Trap: reading `ans.size()` **inside** the loop makes it an infinite loop — snapshot it first.
- **Pick / not-pick recursion** *(the binary-decision view)* — the "My Solution" above. **O(2ⁿ · n)** / **O(n)**. Best when you want to *narrate* the 2ⁿ decision tree, and it's the mental model behind subset-sum DP.
- **Loop-from-`start` backtracking** *(canonical here)* — **O(2ⁿ · n)** / **O(n)**. Reach for it by default: it's the only shape that extends to duplicates, reuse, target sums, and partitions without a rewrite.
- **Bitmask enumeration** *(iterative, zero call stack — the "can you do it without recursion?" answer)* — each of the 2ⁿ integers `mask ∈ [0, 2ⁿ)` **is** a subset: bit `i` set ⇒ include `nums[i]`. Perfect fit here since `n ≤ 10` ⇒ only 1024 masks.
  ```cpp
  class Solution {
  public:
      vector<vector<int>> subsets(vector<int>& nums) {
          int n = nums.size();
          vector<vector<int>> ans;
          ans.reserve(1 << n);
          for (int mask = 0; mask < (1 << n); ++mask) {   // 0 = {}, 2ⁿ-1 = full set
              vector<int> sub;
              for (int i = 0; i < n; ++i)
                  if (mask & (1 << i)) sub.push_back(nums[i]);
              ans.push_back(sub);
          }
          return ans;
      }
  };
  ```
  **TC:** O(2ⁿ · n) — same as the recursion (you can't beat the output size).  **SC:** **O(1)** auxiliary — no recursion stack at all, which is its one genuine edge. `mask = 0` gives the empty subset for free. Gotchas: `1 << n` **overflows `int` for n ≥ 31** (use `1LL << n`); operator precedence means `mask & (1 << i)` needs its parentheses; and it does **not** extend to duplicates or pruning — the moment constraints appear, go back to backtracking.

## Pitfalls
- **Missing `pop_back()`** — the single most common backtracking bug. Without the un-choose, `temp` keeps stale elements and every later subset is polluted.
- **`helper(start + 1)` instead of `helper(i + 1)`** in the loop template — re-offers skipped elements ⇒ duplicate subsets / permutations instead of combinations.
- **Recording only at leaves in the loop template** — the loop version has no `index == n` base case; if you don't `ans.push_back(temp)` at the top of every call, you lose almost every subset.
- **Forgetting the empty subset** — `[]` is a valid answer and both templates emit it for free (mask 0 / the all-not-pick path). Don't "fix" it away.
- **Passing `temp` by value** — it works (each frame gets its own copy, no backtracking needed) but turns O(n) auxiliary space into O(n) *per frame* and copies constantly. Pass by reference + `pop_back()`.
- **Reaching for a `set<vector<int>>` to dedupe** — unnecessary here (input is unique) and the wrong instinct for [[2-90-subsets-ii|Subsets II]], where the fix is **sort + skip equal siblings**, not a hash set.
- **Bitmask overflow** — `1 << n` is `int` arithmetic; safe at `n ≤ 10` here, UB at `n ≥ 31`. Use `1LL << n` if you reuse the snippet.
- **Claiming you can beat O(2ⁿ)** — you can't; the output alone is 2ⁿ subsets. The only thing to optimise is the *auxiliary* space (bitmask → O(1)).
