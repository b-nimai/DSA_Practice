# 7. 17. Letter Combinations of a Phone Number (LC 17) — Medium
🔗 [Open on LeetCode](https://leetcode.com/problems/letter-combinations-of-a-phone-number/)

**Pattern:** Backtracking — **Cartesian product / fixed-length leaf enumeration**; the "one slot per input position, choices come from a lookup table" shape
**Trigger:** "return **all possible strings** the digits could spell, keypad mapping, any order" → one recursion level **per digit**, loop the letters of that digit, record **only at the leaf** (`index == n`). No `start` index, no dedup guard.

## Problem (1-liner)
Given a string of digits `2–9`, return every string formable by picking one letter from each digit's keypad group.
**Examples:** `"23" → ["ad","ae","af","bd","be","bf","cd","ce","cf"]` · `"2" → ["a","b","c"]` · `"79" → 4×4 = 16 strings`.
**Constraints:** **`0 ≤ digits.length ≤ 4`**, `digits[i] ∈ ['2','9']`.
**Edge case:** **`digits = "" → []`**, *not* `[""]`. This is the entire test-case trap of the problem — the lower bound is **0**, not 1.

## Idea (1-liner)
Each digit is an independent **slot**; the answer set is the **Cartesian product** of the slots' letter groups. Recurse one level per digit, branching over that digit's letters — depth is fixed at `n`, so every leaf is a complete answer and nothing internal is ever recorded.

## Approach
1. **Guard the empty input** — `if (digits.empty()) return {};` before touching the recursion.
2. Build a keypad lookup: index `digits[i] - '2'` into `{"abc","def","ghi","jkl","mno","pqrs","tuv","wxyz"}`.
3. Base case `index == digits.size()` → push the buffer, return.
4. Loop over the letters of the current digit: **choose** `s.push_back(c)` → **explore** `helper(index + 1)` → **un-choose** `s.pop_back()`.
5. Read the group size from the string, never assume 3 — `7` and `9` have **four** letters.

> **Load-bearing insight:** this is the pattern's **fixed-depth** family. Subsets branch on "in or out?" and record at **every** node; permutations branch on "who fills this slot?" and record at the **leaf**. LC 17 is the second shape with the choices supplied by a table instead of by the remaining array — which is exactly why it needs **no `start` index and no dedup guard**: different digits map to **disjoint** letter sets, so two distinct paths can never produce the same string. Uniqueness is structural, for a different reason than in [[5-39-combination-sum|39]].

## Code (clean canonical)
```cpp
class Solution {
    vector<string> keys = {"abc","def","ghi","jkl","mno","pqrs","tuv","wxyz"};

    vector<string> ans;
    string s;

    void helper(int index, const string& digits) {
        if (index == (int)digits.size()) { ans.push_back(s); return; }

        for (char c : keys[digits[index] - '2']) {
            s.push_back(c);               // choose
            helper(index + 1, digits);    // explore
            s.pop_back();                 // un-choose
        }
    }
public:
    vector<string> letterCombinations(string digits) {
        if (digits.empty()) return {};    // "" ⇒ [], not [""]
        helper(0, digits);
        return ans;
    }
};
```
**TC:** **O(4ⁿ · n)** — at most 4 branches per digit, `n` digits, each leaf copies an `n`-char string. **SC:** **O(n)** auxiliary (buffer + recursion depth); output separate.
**Say it as:** "3ⁿ to 4ⁿ leaves depending on how many 7s and 9s; `n ≤ 4`, so the real bound is 256 answers."

## My Solution
```cpp
class Solution {
    void helper(int index, string &digits, string s, vector<string>&str, vector<string>&ans) {
        if (index >= digits.size()) { ans.push_back(s); return; }

        string digitStr = str[digits[index] - '0'];
        for (int i = 0; i < digitStr.size(); i++) {
            helper(index + 1, digits, s + digitStr[i], str, ans);
        }
    }
public:
    vector<string> letterCombinations(string digits) {
        vector<string> str(10, "");
        str[2] = "abc"; str[3] = "def"; str[4] = "ghi"; str[5] = "jkl";
        str[6] = "mno"; str[7] = "pqrs"; str[8] = "tuv"; str[9] = "wxyz";
        vector<string> ans;
        helper(0, digits, "", str, ans);
        return ans;
    }
};
```
**Recursion is correct — one real bug, at the empty input.** `digits = ""` hits `index >= size` immediately and records the empty path: returns **`[""]`**, expected **`[]`**. Sizing `str` to 10 and indexing `- '0'` is a nice touch (no off-by-two risk), and reading `digitStr.size()` rather than hardcoding 3 correctly handles `pqrs`/`wxyz`.

**Refinement 1 — guard the empty string in the caller, not in `helper`.**
```cpp
if (digits.empty()) return ans;
helper(0, digits, "", str, ans);
```
Guarding inside `helper` with `if (s.empty()) return;` is **wrong** — in a `push_back`/`pop_back` refactor the buffer is legitimately empty at the root of every call.

**Refinement 2 — `s + digitStr[i]` copies the whole prefix at every node.** Passing the path **by value** allocates a fresh string per frame: O(n) time *and* O(n) space **per node**, so O(4ⁿ · n) allocations instead of O(4ⁿ), and the live stack holds `n` copies instead of one. Use the shared-buffer idiom you already use in [[1-78-subsets|78]] and [[6-40-combination-sum-ii|40]]:
```cpp
s.push_back(digitStr[i]);          // choose
helper(index + 1, digits, s, str, ans);   // s now by reference
s.pop_back();                      // un-choose
```

**Refinement 3 — hoist the keypad out of the function; drop the `int`/`size_t` mismatch.** Building the table with 8 assignment statements on every call is noise. Make it a **member with a default initializer** so it's constructed once and `helper` can read it without threading it through the parameter list:
```cpp
vector<string> keys = {"abc","def","ghi","jkl","mno","pqrs","tuv","wxyz"};   // index: d - '2'
```
And use `index == (int)digits.size()` — `index >= digits.size()` compares `int` to `size_t` and warns.

## Other Approaches
- **Nested loops, one per digit** *(brute / naive)* — only writable if `n` is known at compile time. `n ≤ 4` makes it *technically* possible; it's the answer that shows you can't generalise. Mention only to dismiss.
- **Backtracking with a shared buffer** *(canonical)* — **O(4ⁿ · n)** / **O(n)**. The default; it's the same skeleton as every other note in this folder.
- **Iterative BFS / cascading product** *(no recursion)* — seed the frontier with `{""}`, then for each digit replace it with `frontier × letters`. Same **O(4ⁿ · n)**, **no call stack**, and it reads as an explicit Cartesian product. Careful: seeding `{""}` reproduces the `[""]` bug unless the empty input is guarded first.
```cpp
vector<string> res = {""};
for (char d : digits) {
    vector<string> next;
    for (const string& prefix : res)
        for (char c : keys[d - '2']) next.push_back(prefix + c);
    res = move(next);
}
```
- **Counting instead of listing** — if asked only "**how many** combinations", it's a one-line product `Π len(group(d))`, **O(n)**. The tell, as always: enumeration is mandatory only because they want the strings themselves.

## Pitfalls
- **`digits = ""` → `[""]`** — the bug. The constraint floor is **0**, and this is the single test case the problem is built around.
- **Hardcoding 3 letters per digit** — `7 → pqrs` and `9 → wxyz` have **four**. Always read the group's length.
- **Recording at every node** — would emit prefixes (`"a"`, `"ad"`) for `"23"`. This family records **only at the leaf**; contrast [[1-78-subsets|78]].
- **Adding a `start` index or a dedup guard** — reflex from [[6-40-combination-sum-ii|40]]/[[2-90-subsets-ii|90]], and wrong here: slots are positional and letter groups are disjoint, so no duplicate can arise.
- **Passing the path by value** — correct but quietly O(n)× more work and stack; see Refinement 2. The classic "works, but shows you don't backtrack" tell.
- **Off-by-two on the lookup** — `digits[i] - '2'` for an 8-entry table vs `- '0'` for a 10-entry one. Pick one and stay consistent; mixing them indexes garbage.
- **Inherited from the pattern:** missing `pop_back()`; forgetting that output size, not depth, dominates the complexity.
