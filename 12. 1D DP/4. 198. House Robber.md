# 4. 198. House Robber (LC 198) — Medium
🔗 [Open on LeetCode](https://leetcode.com/problems/house-robber/)

**Pattern:** 1D DP — **[[1-70-climbing-stairs|70 Climbing Stairs]] with the branches made ASYMMETRIC.** Identical two-back dependency window (`i-1`, `i-2`), so the table again collapses to **two rolling variables**; the changes are **`+` → `max`** (optimise instead of count) and — the real difference — **only one branch carries the weight**. In 746 *both* branches pay a cost; here the "skip" branch takes `dp[i-1]` **bare** and the "rob" branch takes `dp[i-2] + nums[i]`. That asymmetry **is** the adjacency constraint, expressed arithmetically.
**Trigger:** "**maximum** sum/profit" + "**cannot pick two adjacent** elements" (dressed up as security systems, neighbouring houses, consecutive days). The tells: (a) the objective is an **optimum, not a count** ⇒ `max`, (b) at each index the choice set is exactly **{take, skip}** — binary and local, so one recurrence covers it, and (c) the forbidden pair is **adjacency only**, which is what makes the state a single index rather than a set. Whenever "**maximum-weight subset of an array with no two chosen elements adjacent**", you're here — and every variant (circular, on a tree, with a `k`-gap) is this recurrence with the boundary changed.

## Problem (1-liner)
Pick a subset of `nums` with **no two adjacent** indices, maximising the sum.
**Examples:** `[1,2,3,1] → 4` (`1 + 3`) · `[2,7,9,3,1] → 12` (`2 + 9 + 1`, **not** the greedy `7 + 3` or `9 + 1`).
**Constraints:** `1 ≤ n ≤ 100`, `0 ≤ nums[i] ≤ 400` — **all non-negative** (this matters: it's why "rob nothing" is never strictly better, and why `-1` is a safe memo sentinel). Max sum `50 × 400 = 20000`, so `int` is ample.
**Edges:** `n == 1` → `nums[0]` (**the case that breaks most bottom-up first drafts**) · `n == 2` → `max(nums[0], nums[1])` · all zeros → `0` · a single large value among small ones → take it alone.

## Idea (1-liner)
`dp[i] = max(dp[i-1], nums[i] + dp[i-2])` — skip this house, or rob it and jump two back.

## Approach
1. `dp[i]` = the best you can rob **considering houses `0..i`** (not necessarily robbing `i`).
2. **Partition by the last decision at house `i`:** either you **skip** it — then the answer is `dp[i-1]` — or you **rob** it — then `i-1` is forbidden and you may add `dp[i-2]`. Disjoint and exhaustive ⇒ take the `max`.
3. Base: `dp[0] = nums[0]`, `dp[1] = max(nums[0], nums[1])`.
4. Loop `i = 2..n-1`, return `dp[n-1]`. Window is 2 ⇒ two scalars.

> **Load-bearing insight #1 — the asymmetry IS the constraint.** In 746 both branches pay a weight; here the skip branch is `dp[i-1]` **with nothing added**, and the rob branch reaches **two** back. If you ever write `max(dp[i-1] + nums[i], dp[i-2] + nums[i])` you have deleted the adjacency rule and are just summing everything. Say "one branch takes the weight, one skips it" out loud and the recurrence is locked.

> **Load-bearing insight #2 — `dp[i]` means "best over the prefix", not "best if I rob house `i`".** That's why `dp[i-2]` is safe to add: it already includes the option of *not* robbing `i-2`, so the recurrence never needs to look three back. Define `dp` as "must rob `i`" instead and you'd need `max` over all `j ≤ i-2`, an accidental O(n²).

> **Load-bearing insight #3 — `dp[1] = max(nums[0], nums[1])`, not `nums[1]`.** This is *the* signature bottom-up bug (see My Solution). The prefix definition means `dp[1]` must already know it can decline house 1. Note the contrast with 70/91, where the base is the **identity of the combine operator** (`1` for `+`); here, with `max` over a **non-empty** prefix, `dp[0]` is a real value, not an identity.

> **Load-bearing insight #4 — the top-down version has no base-case problem at all.** `if (index < 0) return 0;` makes indices `-1` and `-2` fold to `0` for free. Converting to tabulation is exactly where you must re-derive those two base cases by hand — and that is the single most common conversion bug in 1D DP.

> **Load-bearing insight #5 — greedy fails, and pre-empting it scores.** Two tempting greedies, two one-line counterexamples: **"take every other house"** breaks on `[2,1,1,2]` (alternating gives `2 + 1 = 3`; optimal is `2 + 2 = 4`), and **"take the largest, delete its neighbours, repeat"** breaks on `[4,5,4]` (grabs `5`; optimal is `4 + 4 = 8`). No exchange argument exists because one pick constrains **two** neighbours at once ⇒ table required.

## Code (clean canonical)
```cpp
class Solution {
public:
    int rob(vector<int>& nums) {
        int prev2 = 0, prev1 = 0;               // dp[i-2], dp[i-1]; both 0 = "no houses yet"
        for (int x : nums) {
            int cur = max(prev1, x + prev2);    // skip x  |  rob x
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }
};
```
**TC:** **O(n)** — one pass, O(1) per house.  **SC:** **O(1)** — two ints.
*Why this form needs **no** `n == 1` special case: starting both rolling vars at `0` reproduces the recursion's `index < 0 → 0` base, so the first iteration yields `max(0, nums[0]) = nums[0]` on its own. Prefer it over the table precisely because the base cases disappear.*

**Table form**, if you want `dp[]` visible on the whiteboard:
```cpp
int n = nums.size();
vector<int> dp(n);
dp[0] = nums[0];
if (n > 1) dp[1] = max(nums[0], nums[1]);       // both guards are mandatory
for (int i = 2; i < n; i++) dp[i] = max(dp[i - 1], nums[i] + dp[i - 2]);
return dp[n - 1];
```

## My Solution
**Top-down memoized — ✅ correct.**
```cpp
class Solution {
    int helper(int index, vector<int>& nums, vector<int>& mem) {
        if (index < 0) return 0;
        if (mem[index] != -1) return mem[index];

        int dPick = helper(index - 1, nums, mem);          // don't pick current house
        int pick  = nums[index] + helper(index - 2, nums, mem);

        return mem[index] = max(dPick, pick);
    }
public:
    int rob(vector<int>& nums) {
        int n = nums.size();
        vector<int> mem(n, -1);
        return helper(n - 1, nums, mem);
    }
};
```
**O(n) time, O(n) memo + O(n) stack.** Clean: the `index < 0` guard absorbs *both* out-of-range cases, and it sits **above** the memo lookup, so a negative index never indexes `mem` — the same guard-ordering discipline that keeps [[1-70-climbing-stairs|70]] and [[3-91-decode-ways|91]] in bounds. `mem[index] != -1` is a valid sentinel **only because `nums[i] >= 0`**; with negative values you'd need a separate `visited` array — worth saying out loud rather than being lucky.



1. **Shifted base.** `dp[1] = nums[0]` is the *1-indexed* convention (`dp[i]` = best over the first `i` houses), but the loop and `return dp[n-1]` are *0-indexed*. Fix: `dp[0] = nums[0]; if (n > 1) dp[1] = max(nums[0], nums[1]);`.
2. **`n == 1` writes out of bounds** — `dp` has size 1 and you write `dp[1]`; hence the `if (n > 1)` guard (or use the rolling form, which needs neither).
3. **`rob` is private** — the class has no `public:`.

The lesson generalises: **the recurrence survived the conversion untouched; only the base cases broke.** Whenever you translate top-down → bottom-up, write the base cases from the recursion's guard conditions rather than from memory.

## Other Approaches
- **Brute force / subset enumeration** — try every subset, reject those with adjacent picks. **O(2ⁿ · n)** time, **O(n)** stack. Name it, then note that the valid subsets are the Fibonacci-many "no two adjacent" ones — still exponential.
- **Naive recursion** — `f(i) = max(f(i-1), nums[i] + f(i-2))`, no memo. **O(2ⁿ)/O(n)**. Kill it by naming the cause: `f(i-2)` is reached from both branches ⇒ the same prefix is recomputed `Fib`-many times.
- **Top-down memoization** — **O(n)/O(n)**. Your version; the mechanical translation and the right first move, since the base cases come free.
- **Bottom-up table** — **O(n)/O(n)**. Drops the stack; the rung where the base cases must be re-derived.
- **Two rolling variables** *(canonical)* — **O(n)/O(1)**. The expected final answer; stopping at memoization is the real interview miss.
- **Follow-ups to pre-empt:** *"the street is a **circle**"* → **[[5-213-house-robber-ii|213 House Robber II]]**: house `0` and `n-1` are now adjacent, so run the same O(1) helper **twice** — on `[0, n-2]` and `[1, n-1]` — and take the `max`, with `n == 1` special-cased. Two linear passes, still O(n)/O(1). *"the houses form a **binary tree**"* → **337 House Robber III**: same take/skip split, but the state becomes a **pair per node** `(robbed, notRobbed)` returned bottom-up in one DFS, O(n). *"no two picks within **k**"* → `dp[i] = max(dp[i-1], nums[i] + dp[i-k-1])`, window widens to `k+1`. *"return **which houses**"* → keep a `parent[]`/backtrack over the `dp` array, O(n) extra. *"values may be **negative**"* → the recurrence still holds, but seed with `max(0, …)` if the empty subset is allowed. *"maximum sum with no two adjacent, but you must pick **exactly k**"* → state gains a dimension, `dp[i][k]`, O(nk).

> **The 70 / 746 / 91 / 198 quartet to distinguish out loud:** same two-back window, four merge rules. **70** → `dp[i-1] + dp[i-2]`, `+` counts, branches **unconditional**. **746** → `min(dp[i-1] + w, dp[i-2] + w)`, `min` optimises, **both** branches pay. **91** → `dp[i-1] + dp[i-2]`, `+` counts, branches **conditional on a validity predicate**. **198** → `max(dp[i-1], dp[i-2] + nums[i])`, `max` optimises with **asymmetric** branches (one skips the weight). Name the combine operator, the weight placement, and the guard — you've named the problem.

## Pitfalls
- **`dp[1] = nums[1]` (or `nums[0]`) instead of `max(nums[0], nums[1])`** — *the* signature bug. The prefix definition means `dp[1]` must already be allowed to decline house 1.
- **Writing `dp[1]` without an `n > 1` guard** — out-of-bounds on a single-house input. The rolling-variable form sidesteps it entirely; prefer it.
- **Mixing 1-indexed bases with a 0-indexed loop/return** — pick one convention *before* writing the base cases, since the recurrence looks identical either way and won't warn you.
- **Adding the weight to both branches** — `max(dp[i-1] + nums[i], dp[i-2] + nums[i])` silently deletes the adjacency constraint.
- **Defining `dp[i]` as "best if I rob house `i`"** — then `dp[i-2]` is no longer enough and you drift into an O(n²) `max` over all `j ≤ i-2`.
- **Reaching for greedy** — alternating picks break on `[2,1,1,2]`; a local pick constrains two neighbours at once, so no exchange argument exists.
- **`mem[index] != -1` with possibly-negative values** — safe here only because `nums[i] >= 0`; otherwise use a separate `visited` array.
- **Memo lookup placed above the `index < 0` guard** (top-down) — negative index into `mem`. Same trap as 70 and 91.
- **Forgetting to write the memo before returning** — still correct, still O(2ⁿ); surfaces as **TLE, not WA**.
- **Updating rolling variables without a temporary** — stage in `cur`; assigning `prev1` first destroys what `prev2` needs.
- **Reflexive `long long`** — max sum is `50 × 400 = 20000`. Say the bound, don't guess.
- **Stopping at the memoized version** — correct but mid-ladder; walk it to O(1) space.
