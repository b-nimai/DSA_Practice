# 1D DP — Index

60-second whole-pattern recall. Read the **Trigger** column and try to recall the **Idea** before peeking.

**Core skeleton:** define `dp[i]` = the answer for the prefix ending at `i`, **partition by the LAST decision** (the cases must be **disjoint and exhaustive**), then combine: **`+` to count**, **`min`/`max` to optimise**. Compute bottom-up in dependency order. **Check the dependency window before allocating a table** — if `dp[i]` reads only the last `k` states, the `O(n)` array collapses to `k` scalars, and that is the single most reusable move in this pattern. Top-down memoization is the same recurrence written the mechanical way; reach for it when the bottom-up ordering isn't obvious, then convert.

| 1 | [Climbing Stairs](https://leetcode.com/problems/climbing-stairs/) | 70 | E | "**in how many distinct ways**" + "each move is **1 or 2 steps**" + input is a **single scalar `n`** (the answer counts **orderings** — `1+2 ≠ 2+1` ⇒ compositions, not combinations, so no `C(n,k)` formula; the choice set is identical at every position) | **The ROOT of the pattern — `ways(i) = ways(i-1) + ways(i-2)`, i.e. Fibonacci shifted by one (`ways(n) = Fib(n+1)`).** **Why: partition by the LAST move** — you reached step `i` from `i-1` (a 1-step) or from `i-2` (a 2-step); those path sets are **disjoint** (different final move) and **exhaustive** (no third option) ⇒ just **add** them. That "disjoint + exhaustive ⇒ sum" line is the whole technique behind counting DP; say it before writing code. **`ways(0) = 1`, NOT 0** — *the* signature bug: there is exactly one way to climb zero steps (do nothing, the empty product), and zeroing it collapses the chain (`n=2` → 1 instead of 2). **The window is 2 ⇒ two scalars suffice:** `prev2 = prev1 = 1; for (i = 2..n) { cur = prev1 + prev2; prev2 = prev1; prev1 = cur; } return prev1;` — needs the temporary `cur` (assigning `prev1` first destroys what `prev2` needs), and `n == 1` falls out free (loop never runs). **Overflow:** `Fib(46) = 1836311903 < 2³¹−1`, so `int` fits and the `n ≤ 45` constraint exists exactly for that — `long long` is reflex, not reasoning. Top-down trap: with `mem` sized `n+1` and a `helper(index + 2)` branch, `index` reaches `n+1`, so it's in-bounds **only because both base cases (`index == n` → 1, `index > n` → 0) return before the `mem[index]` line** — reorder the guards below the lookup and it's an OOB read; and forgetting to *write* the memo silently degrades to O(2ⁿ) (shows up as TLE, not WA). Ladder: naive recursion **O(2ⁿ)/O(n)** (same subtree recomputed — ~10⁹ calls at n=45) → memoized top-down **O(n)/O(n)** → bottom-up table **O(n)/O(n)** → **two rolling vars O(n)/O(1)** (the expected answer — stopping at memoization is the real interview miss) → matrix power `[[1,1],[1,0]]ⁿ` **O(log n)**, only for "what if n were 10¹⁸ mod p"; Binet's `φⁿ/√5` is a trap (`double` breaks near n≈71). Variants: **1137** (window of 3), **746** (`min` + cost), **198** (`max` + a skip), **91** (window of 2, branches *conditional*), **62** (the 2D version of the same argument) | O(n) | O(1) |
| 2 | [Min Cost Climbing Stairs](https://leetcode.com/problems/min-cost-climbing-stairs/) | 746 | E | "**minimum cost** to climb" + "**one or two steps**" + "start at index **0 or 1**" + reach the "**top of the floor**" (an **optimum, not a count** ⇒ combine with `min`; and "top of the *floor*" — not "last step" — is the entire off-by-one warning) | **70 with the combine operator swapped:** identical two-back window, `+` → `min`, plus a per-step weight. `dp[i]` = min cost to **reach** step `i` (not yet having paid `cost[i]`) ⇒ `dp[i] = min(dp[i-1] + cost[i-1], dp[i-2] + cost[i-2])`, base **`dp[0] = dp[1] = 0`** (both entries free), answer **`dp[n]`**. **Why: partition by the LAST move** — you came from `i-1` or `i-2`, disjoint + exhaustive; counting *sums* the branches, optimising takes the *better* one. That operator swap is the whole difference from 70. **Signature bug: returning `dp[n-1]`** — the top is **one past** the array, so loop `i <= n`; on `[10,15,20]` `dp[n-1]` gives `10`, not `15`. **Second bug: cost on the wrong state** — you pay to *step onto* a step, so it's `dp[i-1] + cost[i-1]`, never `+ cost[i]`; and `dp[0] = cost[0]` double-charges. **Base is `0`, not `1`** — the empty answer is the **identity of the combine operator**: `1` for a count (70), `0` for a sum of costs. Rolling form: `prev2 = prev1 = 0; for (i = 2..n) { cur = min(prev1 + cost[i-1], prev2 + cost[i-2]); prev2 = prev1; prev1 = cur; } return prev1;` — `n == 2` falls out free. **Greedy fails** — example 2 `[1,100,1,1,1,100,1,1,100,1] → 6` is the counterexample: the locally-cheapest step can force a `100` later, no exchange argument ⇒ table required. Suffix/top-down variant: `helper(i) = cost[i] + min(helper(i+1), helper(i+2))`, answer `min(helper(0), helper(1))` — one shared memo is safe **only because `helper(i)` is a pure suffix answer**, independent of where you started. Ladder: naive **O(2ⁿ)** → memo **O(n)/O(n)** → table **O(n)/O(n)** → **two rolling vars O(n)/O(1)** (expected answer); in-place `cost[i] += min(cost[i-1], cost[i-2])` is O(1) but **mutates the input**. Overflow: `1000 × 999 < 10⁶`, `int` is ample. Triple to distinguish: **70** `+` counts · **746** `min`, **both** branches pay · **198** `max`, branches **asymmetric** (one skips) | O(n) | O(1) |
| 3 | [Decode Ways](https://leetcode.com/problems/decode-ways/) | 91 | M | "**how many ways** to decode" + a **digit string** + "**some codes are contained in other codes**" (`"2"`/`"5"` vs `"25"`) — a **count of groupings** ⇒ combine with `+`; and the statement spending its whole example budget on `"06"` being invalid is the flashing sign that **leading zeros, not the recurrence, are the test** | **70 with the branches made CONDITIONAL.** Same two-back window, same `+` combine; each term is merely **gated by a validity predicate**: `dp[i] = dp[i-1]·[s[i-1] ≠ '0'] + dp[i-2]·[10 ≤ s[i-2..i-1] ≤ 26]`, base **`dp[0] = 1`** (empty string decodes one way), `dp[1] = (s[0] != '0')`, answer `dp[n]`. **The recurrence is free — the guards are the entire problem.** **Zeros are the whole problem:** a `0` **cannot stand alone** and **cannot lead** a two-digit code, so it survives *only* as the second digit of **`10` or `20`** ⇒ `"30"` → 0, `"100"` → 0 (both `1\|00` and `10\|0` strand a zero), `"101"` → 1, `"10"` → 1, `"27"` → 1. **Signature bug: writing the two-digit guard as `two <= 26` only** — it accepts `"06"` (`two = 6`) and overcounts; the check is a **range**, `10 ≤ two ≤ 26`, and the **lower bound *is* the leading-zero rule** expressed arithmetically. **Never add an explicit "if undecodable return 0"** — when both guards fail `dp[i]` stays `0` and propagates forward by itself. Rolling form: `prev2 = prev1 = 1; for (i = 2..n) { cur = 0; if (s[i-1] != '0') cur += prev1; two = (s[i-2]-'0')*10 + (s[i-1]-'0'); if (two >= 10 && two <= 26) cur += prev2; prev2 = prev1; prev1 = cur; } return prev1;` — `n == 1` falls out free. Top-down suffix variant `ways(i) = [valid 1]·ways(i+1) + [valid 2]·ways(i+2)` with `ways(n) = 1`; a `mem` of size `n` is in-bounds **only because the `index == n` base returns before the `mem[index]` line** (same trap as 70), and `substr`+`stoi` per check heap-allocates — use digit arithmetic. Ladder: naive **O(2ⁿ)** (`Fib(101)` calls on all-1s at n=100) → memo **O(n)/O(n)** → table **O(n)/O(n)** → **two rolling vars O(n)/O(1)**. Overflow: the problem *states* the answer fits in 32 bits — note it, don't reflex to `long long`. Follow-up: **639 Decode Ways II** (`*` wildcard ⇒ each guard becomes a **weighted** count — `*`→9, `1*`→9, `2*`→6 — mod `10⁹+7`); swap `+` for `\|\|` and it's **139 Word Break**. Quartet: **70** `+` unconditional · **746** `min`, both pay · **91** `+` **conditional** · **198** `max`, **asymmetric** skip | O(n) | O(1) |
| 4 | [House Robber](https://leetcode.com/problems/house-robber/) | 198 | M | "**maximum** sum/profit" + "**cannot pick two adjacent** elements" (security systems, neighbouring houses, consecutive days) — an **optimum, not a count** ⇒ `max`; the choice set at each index is exactly **{take, skip}**, and the forbidden pair is **adjacency only**, which is what keeps the state a single index | **70 with the branches made ASYMMETRIC.** Same two-back window, `+` → `max`, and — the real difference — **only one branch carries the weight**: `dp[i] = max(dp[i-1], nums[i] + dp[i-2])`, base **`dp[0] = nums[0]`, `dp[1] = max(nums[0], nums[1])`**, answer `dp[n-1]`. In **746 both** branches pay a cost; here the skip branch takes `dp[i-1]` **bare** while the rob branch reaches **two** back — **that asymmetry IS the adjacency constraint**. Write `max(dp[i-1] + nums[i], dp[i-2] + nums[i])` and you have deleted the rule and are just summing. **`dp[i]` = best over the PREFIX `0..i`, not "best if I rob `i`"** — that's why `dp[i-2]` suffices (it already contains the option of skipping `i-2`); define it the other way and you drift into an O(n²) `max` over all `j ≤ i-2`. **Signature bug: `dp[1] = nums[1]` (or `nums[0]`) instead of `max(nums[0], nums[1])`** — the prefix definition means `dp[1]` must already be allowed to decline house 1; and writing `dp[1]` at all is **OOB when `n == 1`**, so it needs an `if (n > 1)` guard. Note the base-case contrast with 70/91: there it's the **identity of `+`** (`1`); here, `max` over a **non-empty** prefix makes `dp[0]` a real value. Rolling form kills both problems: `prev2 = prev1 = 0; for (int x : nums) { cur = max(prev1, x + prev2); prev2 = prev1; prev1 = cur; } return prev1;` — starting at `0,0` reproduces the recursion's `index < 0 → 0` base, so `n == 1` falls out free. **Top-down needs no base cases at all** (`if (index < 0) return 0;` folds `-1` and `-2`), which is exactly why the **conversion** to tabulation is where people break it: **the recurrence survives untouched, only the bases break** — derive them from the recursion's guards. `mem[i] != -1` is a legal sentinel **only because `nums[i] >= 0`**. **Greedy fails:** "every other house" breaks on `[2,1,1,2]` (3 vs 4), "largest first, delete neighbours" breaks on `[4,5,4]` (5 vs 8) — one pick constrains **two** neighbours, no exchange argument. Ladder: brute-force subsets **O(2ⁿ·n)** → naive recursion **O(2ⁿ)** → memo **O(n)/O(n)** → table **O(n)/O(n)** → **two rolling vars O(n)/O(1)**. Overflow: `50 × 400 = 20000`, `int` is ample. Variants: **213** (circular → run the linear solver twice, on `[0,n-2]` and `[1,n-1]`, `max` of the two), **337** (tree → a `(robbed, notRobbed)` pair per node in one DFS), no-two-within-`k` → `dp[i-k-1]`. Textbook name: **max-weight independent set on a path**. Quartet: **70** `+` unconditional · **746** `min`, both pay · **91** `+` **conditional** · **198** `max`, **asymmetric** skip | O(n) | O(1) |

## When to reach for 1D DP
1. **"How many ways / distinct sequences"** over a linear structure → counting DP, combine with `+`.
2. **"Minimum / maximum cost, and every element forces a local choice"** → optimisation DP, combine with `min`/`max`.
3. **A greedy is tempting but the local choice is NOT provably forced** → the moment you can't write an exchange argument, you need a table (contrast Jump Game, where the choice *is* forced).
4. **The state is a single index (plus maybe a tiny flag)** → 1D. Two independent indices (two strings, a grid) ⇒ 2D DP.

## Common Pitfalls Across the Pattern
- **The base case for "empty" is 1 when counting, 0 when summing costs** — `ways(0) = 1` (one empty way) but `cost(0) = 0`. Getting this backwards breaks every derived value.
- **Allocating a full table for a fixed-width window** — check what `dp[i]` actually reads before writing `vector<int> dp(n+1)`.
- **Rolling variables updated in the wrong order** — always stage the new value in a temporary first.
- **Memoizing without writing back** — still correct, still exponential; the failure mode is TLE, so it hides.
- **Counting vs ordering** — if `1+2` and `2+1` are distinct, no combinatorics shortcut applies.
- **Reflexive `long long`** — state the growth bound out loud instead of guessing; DP answers that grow like Fibonacci overflow `int` around index 47.
