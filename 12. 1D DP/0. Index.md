# 1D DP — Index

60-second whole-pattern recall. Read the **Trigger** column and try to recall the **Idea** before peeking.

**Core skeleton:** define `dp[i]` = the answer for the prefix ending at `i`, **partition by the LAST decision** (the cases must be **disjoint and exhaustive**), then combine: **`+` to count**, **`min`/`max` to optimise**. Compute bottom-up in dependency order. **Check the dependency window before allocating a table** — if `dp[i]` reads only the last `k` states, the `O(n)` array collapses to `k` scalars, and that is the single most reusable move in this pattern. Top-down memoization is the same recurrence written the mechanical way; reach for it when the bottom-up ordering isn't obvious, then convert.

| 1 | [Climbing Stairs](https://leetcode.com/problems/climbing-stairs/) | 70 | E | "**in how many distinct ways**" + "each move is **1 or 2 steps**" + input is a **single scalar `n`** (the answer counts **orderings** — `1+2 ≠ 2+1` ⇒ compositions, not combinations, so no `C(n,k)` formula; the choice set is identical at every position) | **The ROOT of the pattern — `ways(i) = ways(i-1) + ways(i-2)`, i.e. Fibonacci shifted by one (`ways(n) = Fib(n+1)`).** **Why: partition by the LAST move** — you reached step `i` from `i-1` (a 1-step) or from `i-2` (a 2-step); those path sets are **disjoint** (different final move) and **exhaustive** (no third option) ⇒ just **add** them. That "disjoint + exhaustive ⇒ sum" line is the whole technique behind counting DP; say it before writing code. **`ways(0) = 1`, NOT 0** — *the* signature bug: there is exactly one way to climb zero steps (do nothing, the empty product), and zeroing it collapses the chain (`n=2` → 1 instead of 2). **The window is 2 ⇒ two scalars suffice:** `prev2 = prev1 = 1; for (i = 2..n) { cur = prev1 + prev2; prev2 = prev1; prev1 = cur; } return prev1;` — needs the temporary `cur` (assigning `prev1` first destroys what `prev2` needs), and `n == 1` falls out free (loop never runs). **Overflow:** `Fib(46) = 1836311903 < 2³¹−1`, so `int` fits and the `n ≤ 45` constraint exists exactly for that — `long long` is reflex, not reasoning. Top-down trap: with `mem` sized `n+1` and a `helper(index + 2)` branch, `index` reaches `n+1`, so it's in-bounds **only because both base cases (`index == n` → 1, `index > n` → 0) return before the `mem[index]` line** — reorder the guards below the lookup and it's an OOB read; and forgetting to *write* the memo silently degrades to O(2ⁿ) (shows up as TLE, not WA). Ladder: naive recursion **O(2ⁿ)/O(n)** (same subtree recomputed — ~10⁹ calls at n=45) → memoized top-down **O(n)/O(n)** → bottom-up table **O(n)/O(n)** → **two rolling vars O(n)/O(1)** (the expected answer — stopping at memoization is the real interview miss) → matrix power `[[1,1],[1,0]]ⁿ` **O(log n)**, only for "what if n were 10¹⁸ mod p"; Binet's `φⁿ/√5` is a trap (`double` breaks near n≈71). ## When to reach for 1D DP
1. **"How many ways / distinct sequences"** over a linear structure → counting DP, combine with `+`.
2. **"Minimum / maximum cost, and every element forces a local choice"** → optimisation DP, combine with `min`/`max`.
3. **A greedy is tempting but the local choice is NOT provably forced** → the moment you can't write an exchange argument, you need a table (contrast Jump Game, where the choice *is* forced).
4. **The state is a single index (plus maybe a tiny flag)** → 1D. Two independent indices (two strings, a grid) ⇒ 2D DP.

## Common Pitfalls Across the Pattern
- **The base case for "empty" is 1 when counting, 0 when summing costs** — `ways(0) = 1` (one empty way) but `cost(0) = 0`. Getting this backwards breaks every derived value.
- **Allocating a full table for a fixed-width window** — check what `dp[i]` actually reads before writing `vector<int> dp(n+1)`.
- **Rolling variables updated in the wrong order** — always stage the new value in a temporary first.
- **Memoizing without writing back** — still correct, still exponential; the failure mode is TLE, so it hides.
- **Counting vs ordering** — if `1+2` and `2+1` are distinct, no combinatorics shortcut applies.
- **Reflexive `long long`** — state the growth bound out loud instead of guessing; DP answers that grow like Fibonacci overflow `int` around index 47.
