# 10. 378. Kth Smallest Element in a Sorted Matrix (LC 378) — Medium
🔗 [Open on LeetCode](https://leetcode.com/problems/kth-smallest-element-in-a-sorted-matrix/)

**Pattern:** Heap — **Top-K on a sorted grid**, but the problem *forbids* the naive size-K heap by capping memory ⇒ the real answers are a **min-heap of one candidate per row (O(n))** and **binary search on the answer value (O(1))**
**Trigger:** "kth smallest in a matrix where **every row AND every column is sorted**, with **memory better than O(n²)**" → the memory clause is the whole problem. Two escapes: **k-way merge** (min-heap seeded with each row's head) or **binary search the value + staircase count**.

## Problem (1-liner)
Given an `n × n` matrix whose **rows and columns are each sorted ascending**, return the **kth smallest element in sorted order** — *not* the kth **distinct** element (duplicates are counted separately).
**Examples:** `matrix=[[1,5,9],[10,11,13],[12,13,15]], k=8 → 13` — flattened sorted it's `[1,5,9,10,11,12,13,13,15]`, and the 8th is the **second** `13`; if it were "kth distinct" the answer would be `15` · `matrix=[[-5]], k=1 → -5` — single cell, negative value.
**Constraints:** `1 ≤ n ≤ 300` (so `n² ≤ 90 000`), `-10^9 ≤ matrix[i][j] ≤ 10^9`, `1 ≤ k ≤ n²`. **Required: memory better than O(n²).** **Follow-up: O(1) memory.** **Edge cases:** `n == 1`; `k == 1` (always `matrix[0][0]`) and `k == n²` (always `matrix[n-1][n-1]`); an entire matrix of equal values; negatives (the value range spans 2·10⁹ → **overflow trap in `mid`**).

## Idea (1-liner)
The matrix is **not fully sorted** — it's `n` sorted lists that are also column-wise sorted, i.e. a **partially ordered set**. So either (a) **merge the n rows** and stop after `k` pops, carrying only one live candidate per row → **O(n)** memory; or (b) forget the elements entirely and **binary search the answer's value**, since `count(≤ v)` is monotonic in `v` and countable in **O(n)** with a staircase walk → **O(1)** memory.

## Approach
**Canonical (k-way merge, O(n) space):**
1. Push the **head of each row** `{matrix[i][0], i, 0}` into a **min-heap** (only `min(n, k)` rows can ever matter).
2. Pop the global minimum `k` times. Each pop is the next element in overall sorted order.
3. After popping `{val, r, c}`, push its **right neighbour** `{matrix[r][c+1], r, c+1}` if `c+1 < n` — that row's next-smallest.
4. The `k`-th popped value is the answer.

**Optimal (binary search on value, O(1) space):**
1. `lo = matrix[0][0]`, `hi = matrix[n-1][n-1]` — the answer must lie in this range.
2. For `mid`, count how many elements are `≤ mid`: start at the **top-right** corner, walk **down** the rows and slide `c` **left** while `matrix[r][c] > mid`; add `c + 1` per row. `c` never resets ⇒ the whole count is **O(n)**, not O(n²).
3. `cnt < k` → the answer is bigger, `lo = mid + 1`. Else `hi = mid` (keep `mid` as a candidate — it might be the answer itself).
4. Converge to `lo`.

> **Load-bearing insight:** binary searching the **value** instead of an index is legal because `count(≤ v)` is **monotonically non-decreasing** in `v`, and the `hi = mid` (never `mid - 1`) branch means the loop converges to the **smallest value whose count reaches k** — which is *always an element that actually exists in the matrix*, even though `mid` itself was just an arbitrary number in the range. That surprise (searching over numbers, landing on a real cell) is exactly what interviewers probe. The staircase count is the second half: because both rows and columns are sorted, the boundary between "≤ mid" and "> mid" is a **monotone staircase**, so one pointer sweeps it in O(n).

## Code (clean canonical)
```cpp
class Solution {
public:
    int kthSmallest(vector<vector<int>>& matrix, int k) {
        int n = matrix.size();
        // {value, row, col} — min-heap over the n row-heads
        priority_queue<array<int,3>, vector<array<int,3>>, greater<>> pq;

        for (int i = 0; i < min(n, k); i++)
            pq.push({matrix[i][0], i, 0});

        while (--k) {                                  // pop k-1 times, k-th is left on top
            auto [val, r, c] = pq.top(); pq.pop();
            if (c + 1 < n) pq.push({matrix[r][c + 1], r, c + 1});
        }
        return pq.top()[0];
    }
};
```
**TC:** O(min(n,k) + k log n) — heap holds ≤ n entries, k pops.  **SC:** **O(n)** — satisfies "better than O(n²)". This is the expected heap answer.

## My Solution
```cpp
class Solution {
public:
    int kthSmallest(vector<vector<int>>& matrix, int k) {
        priority_queue<int> pq;                        // max-heap of size k

        for (int i = 0; i < matrix.size(); i++) {
            for (int j = 0; j < matrix[0].size(); j++) {
                pq.push(matrix[i][j]);
                if (pq.size() > k) pq.pop();           // evict the current largest
            }
        }
        return pq.top();
    }
};
```
**Produces the right answer, but violates the problem's memory clause.** The size-K max-heap for "k smallest" is the correct [[1-215-kth-largest-element-in-an-array|215]] polarity flip, and duplicates are handled for free (each `13` is pushed separately, so `k=8` lands on the second one). Two problems: (1) **SC is O(k), and `k` can be `n²`** — with `k = n²` the heap holds the entire matrix, which is exactly the O(n²) the statement forbids; (2) it **never uses the sortedness** — the identical code would run on a shuffled matrix, which is the tell an interviewer waits for. TC **O(n² log k)** vs O(k log n). Also `pq.size() > k` mixes `size_t` with `int` (harmless here since `k ≥ 1`, but cast it). **Keep it as your fallback answer, then immediately say "but the memory bound rules this out" and pivot to the k-way merge.**

## Other Approaches
- **Flatten to a 1-D vector, sort, index `k-1`** *(brute)* — **O(n² log n)** / **O(n²)** memory. Explicitly banned by the statement, but say it out loud first as the baseline you're improving on.
- **`nth_element` on the flattened array** *(brute+)* — average **O(n²)** / O(n²). Faster than sorting, same illegal memory.
- **Size-K max-heap over all n² cells** *(your solution)* — **O(n² log k)** / **O(k) → O(n²) worst case**. Passes the judge, fails the stated constraint. The right instinct from the Top-K family, wrong problem to apply it to.
- **k-way merge with a min-heap of row heads** *(canonical)* — **O(k log n)** / **O(n)**. See above. This is the "uses sortedness + legal memory" answer.
- **Binary search on the value + staircase count** *(optimal, answers the follow-up)* — **O(n · log(hi−lo))** ≈ n·31 / **O(1)**. The only approach that hits constant memory:
  ```cpp
  int kthSmallest(vector<vector<int>>& matrix, int k) {
      int n = matrix.size();
      int lo = matrix[0][0], hi = matrix[n-1][n-1];
      while (lo < hi) {
          int mid = lo + (hi - lo) / 2;          // NOT (lo+hi)/2 — values reach ±1e9
          int cnt = 0, c = n - 1;
          for (int r = 0; r < n; r++) {          // staircase from the top-right
              while (c >= 0 && matrix[r][c] > mid) c--;
              cnt += c + 1;                      // c never resets ⇒ O(n) total
          }
          if (cnt < k) lo = mid + 1;
          else         hi = mid;
      }
      return lo;                                  // guaranteed to be a real matrix value
  }
  ```
- *(Mentionable only)* **Selection in a sorted matrix in O(n)** — the paper the follow-up links (Frederickson & Johnson). Name it, don't attempt it.

## Pitfalls
- **The memory clause is the problem.** Any solution that materialises all n² values (sort, `nth_element`, size-K heap when `k = n²`) is rejected on paper even though LeetCode accepts it. Read the constraint before choosing the heap.
- **`(lo + hi) / 2` overflows** — values span `-10^9 … 10^9`, so the sum reaches 2·10⁹ > `INT_MAX`. Always `lo + (hi - lo) / 2`.
- **`hi = mid`, never `hi = mid - 1`** — `mid` may *be* the answer. Pair it with `while (lo < hi)` (not `<=`), or you infinite-loop.
- **Don't `return mid`** inside the binary search when `cnt == k` — `mid` need not exist in the matrix, and a *larger* value can share the same count. Only the converged `lo` is guaranteed to be a real element.
- **Reset `c` per row and the count silently becomes O(n²)** — the whole point of the staircase is that the pointer only ever moves left, once, across all rows.
- **kth smallest ≠ kth distinct** — same trap as [[1-215-kth-largest-element-in-an-array|215]]. `k=8` on Example 1 is the *second* `13`. Never de-duplicate.
- **Heap version: `min(n, k)` seeds** — pushing all n rows when `k < n` is wasted work (harmless, but say the bound).
- **Heap version: push the right neighbour, not the one below** — pushing downward re-visits cells and double-counts; one live candidate **per row** is the invariant.
- **`while (--k)` pops exactly `k-1` times** — leaving the kth on top. Off-by-one here (`while (k--)`) returns the (k+1)th.
- **A sorted-rows-and-columns matrix is NOT a sorted 1-D array** — `matrix[i][j]` and `matrix[i+1][j-1]` are incomparable, so you cannot binary search *positions* (that only works for LC 74's fully-sorted matrix). You binary search **values**.
- **Unsigned `size()`** — `pq.size() > k` mixes `size_t` and `int`; cast it.
